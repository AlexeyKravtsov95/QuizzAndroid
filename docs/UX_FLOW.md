# UX_FLOW.md — «По порядку!»

Пользовательские потоки, состояния экранов и краевые случаи. Статус: утверждено, 2026-08-30.

Этот документ описывает **поведение и состояния**, а не внешний вид. Палитра, шрифты, скругления, тени, размеры и отступы задаются отдельным комплектом дизайн-документов (`DESIGN_PRINCIPLES.md`, `DESIGN_TOKENS.md`, `COMPONENTS.md`) и не выбираются при написании кода — см. Design Gate в `ARCHITECTURE.md` и `IMPLEMENTATION_PLAN.md`. Там, где здесь встречается «крупно», «приглушённый терракотовый» или «мягкая тень», это указание на роль элемента, а конкретное значение берётся из `DESIGN_TOKENS.md`.

## 1. Карта экранов

Six экранов, single-activity, один `NavHost`.

```
                      ┌──────────────┐
                      │   Home       │◀────────────────┐
                      │ (start dest) │                 │
                      └──────┬───────┘                 │
            ┌────────────────┼─────────────────┐       │
            ▼                ▼                 ▼       │
      ┌──────────┐    ┌────────────┐    ┌──────────┐   │
      │ Archive  │    │  Settings  │    │  Puzzle  │   │
      └────┬─────┘    └────────────┘    │ {index}  │   │
           │                            └────┬─────┘   │
           ▼                                 │ проверка│
      ┌──────────┐                           ▼         │
      │ DayRecap │                     ┌────────────┐  │
      │ {date}   │◀────────────────────│PuzzleResult│  │
      │ (просмотр)│      после 3-й     │  {index}   │  │
      └──────────┘                     └─────┬──────┘  │
                                             │ 1→2→3   │
                                             └─────────┘
                    DayRecap {today} ─── «Готово» ──────┘
```

### Маршруты

| Route | Экран | Аргументы |
| --- | --- | --- |
| `home` | Главный | — |
| `puzzle/{puzzleIndex}` | Игровой | `puzzleIndex: Int` (0..2) |
| `puzzle/{puzzleIndex}/result` | Результат головоломки | `puzzleIndex: Int` |
| `recap/{date}` | Итог дня | `date: String` (ISO `yyyy-MM-dd`) |
| `archive` | Архив и статистика | — |
| `settings` | Настройки | — |

Соображения по навигации:

- `Puzzle` и `PuzzleResult` — разные маршруты, а не состояния одного экрана. Причина: разное содержимое системной кнопки «назад», разный набор действий, отдельные заголовки для TalkBack. Общая ViewModel игровой сессии живёт на уровне вложенного графа `dailySession`, а не отдельного экрана.
- `recap/{date}` используется и для итога сегодняшнего дня, и для просмотра дня из архива. Отличие — только в наличии кнопки «Поделиться» (есть в обоих) и заголовке («Сегодня» / дата).
- Переход `PuzzleResult(2) → recap/today` вычищает граф `dailySession` из бэкстека: `popUpTo("home")`. Возврат «назад» с итога дня ведёт на `Home`, а не обратно в задания.
- Bottom navigation нет: три раздела (архив, настройки) вызываются иконками в шапке `Home`. Постоянная нижняя панель на экране с перетаскиванием — лишний источник промахов.

## 2. Состояние первого запуска

Отдельного splash и onboarding нет по требованию. Обучение контекстное и одноразовое.

### Home при первом запуске

- Заголовок «По порядку!», под ним одна строка: «Три задания в день. Расставьте карточки в правильном порядке».
- Карточка задания дня: «Задание дня · 3 головоломки · 2–4 минуты», кнопка **«Начать»** вместо «Играть».
- Блок серии и статистики **скрыт** (пустых нулей не показываем — они выглядят как поражение).
- Иконка «Архив» скрыта, пока нет ни одного завершённого дня. Иконка «Настройки» видна всегда.

### Первая головоломка

- Первая карточка списка получает однократную подсказку: сплошная (не полупрозрачная) тональная плашка «Перетащите за ручку или используйте стрелки», занимающая собственное место в потоке контента над первой карточкой, а не оверлей поверх неё, + короткая анимация покачивания (300 мс, один раз). Скрытие подсказки не требует долгого нажатия — реагирует на любое обычное взаимодействие. Плашка исчезает при первом взаимодействии или через 4 секунды — в зависимости от того, что наступит раньше.
- Рядом с заголовком списка постоянно видна подпись направления, например «Сверху — самое раннее».
- Кнопка «Проверить» неактивна первые 600 мс после появления подсказки, чтобы случайный тап не проскочил обучение.

### Права и разрешения

- Разрешение `POST_NOTIFICATIONS` **не запрашивается при первом запуске**. Запрос показывается один раз, на экране `DayRecap` после первого полностью завершённого дня, с человеческой формулировкой: «Напоминать о новом задании?» → «Да, в 9:00» / «Не нужно». Отказ не повторяем; включить можно в настройках.
- Никаких других разрешений приложению не требуется.

### Флаги первого запуска

Хранятся в `UserPreferences`: `hasSeenDragHint`, `hasSeenScoringHint`, `hasCompletedFirstDay`, `notificationPromptShown`. Все — булевы, ни одного счётчика показов.

## 3. Home — состояния

| Состояние | Когда | Что показываем | Основное действие |
| --- | --- | --- | --- |
| `Loading` | Первый кадр, пока читается прогресс и контент | Скелетон карточки дня; блок серии не мигает | — |
| `FirstRun` | Нет ни одной сыгранной головоломки | Карточка дня + одна поясняющая строка, статистика скрыта | «Начать» |
| `Ready` | Сегодня доступен новый набор, ни одно задание не начато | Дата, «День N» (порядковый номер набора пользователя), категория дня не раскрывается, серия, «Лучший день», «Сыграно дней» | «Играть» |
| `InProgress` | Набор назначен на сегодня и пройдено 0–2 задания из 3 | «Задание 2 из 3», прогресс-индикатор из трёх точек, текущий счёт скрыт | «Продолжить» |
| `Completed` | Все 3 задания пройдены | «Сегодня: N из 18», серия, «Следующее задание — через ЧЧ:ММ» | «Посмотреть итог» → `recap/today` |
| `AwaitingNextDay` | Новый набор сегодня не положен: часы переведены назад (`today <= lastAssignedDate`) | Итог последнего пройденного дня и строка «Следующее задание — завтра». Без упоминания часов и без обвинений | «Посмотреть итог» |
| `ContentExhausted` | Все наборы пакета израсходованы (`setIndex` дошёл до последнего) | Честный текст: «Новые задания готовятся. Ваш архив и лучшая серия сохранены», архив и статистика доступны | «Открыть архив» |
| `Error` | Контент не разобран или база недоступна | «Не удалось загрузить задания» + «Повторить»; серия и архив показываются, если прогресс читается | «Повторить» |

Пояснения:

- **Пустого состояния (`Empty`) на Home нет.** Задание есть всегда, пока в пакете остались невыданные наборы; их исчерпание — это `ContentExhausted`, отдельный осмысленный экран, а не «здесь пусто».
- **`Locked` состояния нет.** Задания не запираются по времени: набор доступен целиком с 00:00 локальной даты. Единственная «блокировка» — невозможность переиграть завершённый день, и она выражается состоянием `Completed`, а не замком.
- **Набор не расходуется, пока по нему нет ни одной попытки.** Пока пользователь не нажал «Играть», назначение не записано вовсе; если он нажал «Играть» и вышел, назначение переносится на следующую дату. Расходует набор только первая проверенная головоломка. Подробности — раздел 9.
- **`ContentExhausted` не замораживает текущую серию.** Сохраняются архив, статистика и лучшая серия. Текущая серия прервётся, как любая серия без завершённых дней, — притворяться, что она стоит на паузе, было бы неправдой, и при возврате контента пользователь всё равно обнаружил бы её обнулённой.
- «День N» — порядковый номер набора этого пользователя (1..35), а не номер календарного дня. У двух людей в одну дату номера разные — это следствие последовательной выдачи, и оно не скрывается.
- Обратный отсчёт до следующего дня обновляется раз в минуту, не раз в секунду: секундный таймер выглядит как давление.

## 4. Puzzle — игровой экран

### Компоновка (сверху вниз)

1. Шапка: «Задание 2 из 3», иконка категории, кнопка «Назад».
2. Формулировка задания — 1–2 строки, крупно.
3. Подпись направления сортировки: «Сверху — самое раннее» / «Сверху — самое большое».
4. Четыре карточки в вертикальном списке. Каждая: заголовок, при необходимости — одна строка уточнения, ручка перетаскивания, кнопки ↑ и ↓.
5. Кнопка «Проверить» — закреплена внизу, над системными отступами.

Экран проектируется так, чтобы **на типичном телефоне не было вертикальной прокрутки**: прокрутка одновременно с перетаскиванием — главный источник неуклюжести. Если контент не помещается (крупный шрифт, маленький экран), включается прокрутка, а список перестаёт быть «страницей» — тогда авто-скролл при перетаскивании к краю обязателен.

### Состояния экрана

| Состояние | Условие | Поведение |
| --- | --- | --- |
| `Loading` | Загрузка головоломки | Скелетон, кнопка «Проверить» отключена |
| `Playing` | Обычное состояние | Перестановки не ограничены, «Проверить» активна |
| `Dragging` | Карточка захвачена | Поднятая карточка (elevation), остальные плавно расступаются |
| `Submitting` | Нажата «Проверить» | Все взаимодействия заблокированы, ~150 мс, чтобы избежать двойного нажатия |
| `AlreadyAnswered` | Экран открыт для уже отвеченной головоломки | Немедленный редирект на `puzzle/{i}/result` без промежуточного кадра |
| `Error` | Головоломка не найдена/повреждена | «Задание недоступно» + «Пропустить». Пропущенная головоломка засчитывается как 0 баллов, но день можно завершить |

Пустого состояния у игрового экрана нет: четыре карточки либо есть, либо это `Error`.

### Правило фиксации

Нажатие «Проверить» атомарно записывает попытку (`PuzzleAttempt`) в базу **до** показа результата. Убийство процесса между записью и навигацией не приводит к возможности переиграть.

## 5. PuzzleResult — результат одной головоломки

Показываем:

- строку «N из 6» и, только на третьем результате, накопленный счёт дня — чтобы не превращать сессию в табло;
- **правильный порядок** списком, у каждой карточки — её ключевое значение (год, высота, расстояние). Это то, что делает результат обучающим;
- **перечень перепутанных пар** — по одной строке на каждую. Строк не больше шести, обычно одна-две. Это и есть объяснение потерянных баллов на языке самой головоломки, а не на языке арифметики;
- короткое объяснение (2–3 предложения);
- ссылку/подпись «Источники» — раскрывающийся блок, а не отдельный экран;
- второстепенное действие **«Сообщить о неточности»** — рядом с источниками, мелким шрифтом;
- кнопку «Дальше» (или «К итогу дня» для третьей головоломки).

### «Сообщить о неточности»

Открывает почтовый клиент через `Intent.ACTION_SENDTO` с `mailto:`-ссылкой и предзаполненными полями:

```
Кому:  <адрес из strings.xml>
Тема:  По порядку! — неточность в задании geo-vysota-gor-007
Текст: Задание: geo-vysota-gor-007
       Версия приложения: 1.0.0 (12)
       Версия контента: 3

       Опишите, что не так:
```

Правила:

- **Сети не требует и данных никуда не отправляет.** Приложение только формирует письмо; отправляет его пользователь из своего почтового клиента, видя весь текст. Это не нарушает обещание «ничего не собираем».
- Предзаполняется только `puzzleId`, версия приложения и версия контента — ничего о пользователе, его результатах и прогрессе.
- Если почтового клиента нет (`resolveActivity == null`), действие не показывается вовсе, а адрес доступен в «О приложении» для копирования.
- То же действие дублируется в настройках — как общий канал, без привязки к головоломке.

Это единственный канал обратной связи, работающий быстрее отзывов в магазине. При риске неоднозначной или ошибочной головоломки (R-2 в `PRODUCT.md`) он окупается: узнать об ошибке от первого внимательного пользователя лучше, чем от тридцатого через оценку «2 звезды».

### Формулировка перепутанной пары

Шаблон строки — фиксированный, ровно два варианта:

```
Карточка «{A}» должна располагаться перед карточкой «{B}»
Карточка «{A}» должна располагаться после карточки «{B}»
```

Например: «Карточка „Эльбрус" должна располагаться после карточки „Монблан"».

**Слова «выше» и «ниже» запрещены.** В списке «выше» означает позицию, но в головоломке про высоту гор, глубину впадин или температуру «выше» — это ещё и измеряемая величина, и строка «Эльбрус должен быть выше Монблана» становится двусмысленной ровно там, где она важнее всего. «Перед» и «после» относятся только к положению в списке и не пересекаются ни с одним из допустимых `sortKey`.

По той же причине формулировка не упоминает направление сортировки: пользователь уже видит подпись «Сверху — самая низкая» над списком, и повторять её в объяснении значит смешивать два разных утверждения.

Грамматика: название карточки берётся в кавычки и не склоняется, согласование идёт со словом «карточка» — так шаблон остаётся корректным для любого названия, включая иностранные и аббревиатуры. На узких экранах допустима сокращённая форма «„Эльбрус" — после „Монблан"», TalkBack при этом читает полный вариант.

### Как объясняется парный подсчёт

Парный подсчёт понятнее по ощущению, чем по формулировке: пользователь видит, что «почти угадал» даёт почти полный балл. Но правило нужно объяснить один раз, иначе цифра «5 из 6» выглядит произвольной.

- На **первом в жизни** экране результата под счётом появляется одна строка: «Баллы даются за каждую пару карточек в правильном порядке. У четырёх карточек шесть пар». Показывается однократно, флаг `hasSeenScoringHint`.
- Дальше правило не повторяется: его заменяет перечень перепутанных пар, из которого связь «одна перепутанная пара = минус один балл» видна сама.
- В разделе «О приложении» правило описано постоянно, для тех, кто вернётся к вопросу.

Формулировка «пара в правильном порядке» намеренно предпочтена слову «инверсия»: пользователь не должен встречать терминологию.

### Тон

Анимация появления результата — постепенная (по одной строке, ~60 мс между строками), без победных эффектов и без звука «проигрыша». Результат 6 из 6 отмечается сдержанно — одной строкой «Всё верно», без конфетти. Ноль пар не подсвечивается красным: показываем нейтрально, акцент на объяснении. Перепутанные пары оформляются приглушённым терракотовым, а не сигнальным красным.

Системная кнопка «назад» с этого экрана ведёт на `Home`, а не обратно в игру. Вернуться в отвеченную головоломку нельзя.

## 6. DayRecap — итог дня

Единый экран для «сегодня» и для дня из архива.

- «N из 18» крупно, под ним три строки по головоломкам: категория и результат (например «География · 5 из 6»), без формулировок.
- Серия: «Серия: 6 дней». Если серия обновила рекорд — одна строка «Лучшая серия».
- Кнопка **«Поделиться»** — формирует текстовую карточку без спойлеров:

```
По порядку! · День 12
15/18
🟩🟩🟩🟩🟩🟩
🟩🟩🟩🟩⬜⬜
🟩🟩🟩🟩🟩⬜
Серия: 6 дней
```

Правила карточки:

- три строки по шесть символов — по одной на головоломку, по одному символу на пару. Читается в любом мессенджере моноширинно и без вложений;
- **вместо даты — «День 12»**, порядковый номер набора этого пользователя. Дата убрана намеренно: при последовательной выдаче у двух людей в одну дату разные задания, и дата создавала бы ложное ожидание общего задания. Номер дня честно читается как личный прогресс;
- ни названий заданий, ни категорий, ни правильных порядков — количество верных пар не выдаёт содержание;
- ссылка на приложение — отдельной строкой (текст в ресурсах, ссылка RuStore подставляется на этапе релиза).

- Кнопка «Готово» → `Home` (для сегодняшнего дня) или «Назад» → `Archive`.

Состояния: `Loading`, `Content`, `Error` (день не найден в архиве — «Данные за этот день не сохранились»).

## 7. Archive и статистика

Один экран, две части.

**Статистика** (шапка): сыграно дней, средний балл, лучший день, текущая и лучшая серия.

**Список дней** — по убыванию даты, каждая строка: дата, «День N», «N из 18», три точки-индикатора. Незавершённые дни показываются с пометкой «не завершён» и своим частичным баллом. Тап → `recap/{date}`.

В архиве видны и дата, и номер набора: дата отвечает на «когда я играл», номер — на «сколько я прошёл». Пропущенные календарные дни в списке не появляются вовсе — они не расходовали контент, и показывать по ним пустые строки значило бы упрекать пользователя за пропуск.

Состояния:

| Состояние | Что показываем |
| --- | --- |
| `Loading` | Скелетон списка |
| `Empty` | «Здесь появятся ваши результаты» + кнопка «К заданию дня». Достижимо только если пользователь дошёл до архива через настройки, не сыграв ни дня |
| `Content` | Статистика + список |
| `Error` | «Не удалось прочитать историю» + «Повторить» |

Пагинация не нужна: даже за год это ~365 строк, `LazyColumn` с постраничным чтением из базы по 50 записей.

## 8. Настройки

Плоский список без вложенных экранов:

- Звук — переключатель;
- Вибрация — переключатель;
- Напоминание — переключатель + выбор времени (по умолчанию 9:00). При включении, если разрешения нет, запрашивается системно; при отказе переключатель возвращается в «выкл» и показывается строка «Разрешите уведомления в настройках системы»;
- Тема — «Как в системе» / «Светлая» / «Тёмная»;
- О приложении — версия, автор, набор контента (`contentVersion`), правило подсчёта баллов одной фразой, ссылка на список источников;
- Источники — экран-список или раскрывающийся блок со ссылками по всем сыгранным головоломкам;
- **Сообщить о неточности** — то же `mailto`-действие, что на экране результата, но без привязки к конкретной головоломке. Скрывается, если почтового клиента нет.

Экрана «Сбросить прогресс» в MVP нет: слишком опасное и редкое действие. Оставлено как открытый вопрос.

## 9. Даты, часовые пояса, перезапуск

Это самая рискованная часть логики, поэтому правила зафиксированы явно.

### Определение «сегодня»

- Сегодняшняя дата = `LocalDate.now(ZoneId.systemDefault())`. Никаких UTC-суток: пользователь ожидает, что новый день наступает в его полночь.
- Абстракция `Clock` (`kotlinx.datetime.Clock` или `java.time.Clock`) внедряется, а не берётся статически. Это единственный способ тестировать смену дня.

### Выбор набора: последовательная выдача

Набор **не** привязан к календарной дате глобально. Каждый пользователь проходит наборы по порядку от первого, с какой бы даты он ни начал.

Состояние хранится в таблице назначений `day_assignments`: `local_date → set_index`, где `local_date` уникальна и `set_index` уникален.

Ключевое понятие — **израсходованность**. Назначение считается израсходованным, как только по нему сделана хотя бы одна попытка. Назначение без единой попытки называется **отложенным** (pending) и не расходует контент: оно переносится на следующую дату.

```
decide(today):
    pending = назначение, по которому нет ни одной попытки   // не более одного
    if pending != null:
        if pending.localDate == today:
            return Assigned(pending.setIndex)     // сессия начата, но не сыграна
        if today < pending.localDate:
            return AwaitingNextDay                // часы переведены назад
        return CarryOver(pending.setIndex)        // перенести на сегодня при старте сессии

    // здесь все назначения израсходованы
    todays = assignments[today]
    if todays != null:
        return Assigned(todays.setIndex)          // сегодня уже играли

    lastDate = max(local_date) среди назначений
    if today <= lastDate:
        return AwaitingNextDay
    next = max(set_index) + 1                     // -1 + 1 = 0, если назначений нет
    if next >= setCount:
        return ContentExhausted
    return NewSet(next)                           // ещё НЕ записано
```

### Перенос отложенного назначения

Это то место, где наивная реализация ломается: если оставить старую строку и вставить новую с тем же `setIndex`, ограничение `UNIQUE(pack_id, set_index)` отобьёт вставку, и пользователь получит ошибку вместо задания.

Правильное поведение — **перенос существующей строки, а не создание второй**:

```
UPDATE day_assignments
   SET local_date = :today, assigned_at = :now
 WHERE local_date = :pendingDate
```

Правила переноса:

1. Переносится **та же строка**: `set_index` не меняется, вторая запись с этим индексом не появляется, ограничение уникальности не нарушается.
2. Перенос выполняется **транзакционно, в момент старта сессии** (переход `Home → Puzzle(0)`), вместе с проверкой, что за это время не наступила новая дата.
3. Перенос только **вперёд**. Если `today < pending.localDate` (часы переведены назад), строка остаётся на месте и показывается `AwaitingNextDay` — отложенный набор не теряется и не «уезжает» в прошлое.
4. Отложенное назначение в системе **не более одного**: новое назначение создаётся только когда отложенного нет. Инвариант проверяется тестом.
5. Назначение с хотя бы одной попыткой **израсходовано** и не переносится никогда, даже если день остался незавершённым.

### Что видит пользователь при отложенном назначении

| Ситуация | Состояние Home |
| --- | --- |
| Назначение на **сегодня**, попыток 0 | `InProgress`, кнопка **«Продолжить»** — она открывает первую головоломку набора |
| Назначение на сегодня, попыток 1–2 | `InProgress`, «Продолжить» открывает первую неотвеченную |
| Назначение на **прошлую** дату, попыток 0 | `Ready`, кнопка «Играть»: при нажатии набор переносится на сегодня |

Первая строка — сознательное решение: пользователь, нажавший «Играть» и сразу вышедший, уже начал день, и показывать ему «Играть» заново было бы неправдой. При этом набор он не потерял: если он не вернётся сегодня, тот же набор перенесётся на завтра.

### Правила, которые из этого следуют

1. **Пропущенные дни не расходуют контент.** Индекс растёт от последнего израсходованного набора, а не от календаря. Не открывал приложение неделю — вернулся ровно к следующему набору.
2. **Не более одного нового набора за локальную календарную дату.** Уникальность `local_date` обеспечивает это на уровне базы, а не только логики.
3. **Открыть приложение и уйти — бесплатно**, даже если «Играть» уже нажато: набор переносится.
4. **105 головоломок = 35 активных дней для каждого**, независимо от даты установки.

Порядковый номер, который видит пользователь, — `setIndex + 1` («День 12»). При переносе номер не меняется: день пользователя привязан к набору, а не к календарю.

### Смена даты во время работы приложения

- Приложение слушает `Intent.ACTION_DATE_CHANGED`, `ACTION_TIME_CHANGED`, `ACTION_TIMEZONE_CHANGED` (регистрация в рантайме, пока Activity в `STARTED`) и дополнительно перечитывает дату в `ON_START`.
- Если дата изменилась, **пока пользователь находится в игровой сессии**, сессию не прерываем: незавершённая головоломка доигрывается и записывается на ту дату, для которой была начата. Прерывание в момент перетаскивания — худший из возможных вариантов.
- После возврата на `Home` состояние пересчитывается под новую дату. Если день сменился, показывается новый набор.

### Перевод часов назад / вперёд пользователем

Последовательная выдача сделала эту защиту и проще, и надёжнее, чем при календарной привязке.

- **Часы назад.** Новый набор выдаётся только если сегодняшняя дата строго больше даты последнего начатого набора (`today > lastAssignedDate`). Перевод часов назад поэтому не даёт ни одного дополнительного набора: пользователь попадает в состояние `AwaitingNextDay` — Home показывает последний пройденный итог и строку «Следующее задание — завтра». Это закрывает и сценарий «туда-обратно», которым при наивной проверке «есть ли назначение на эту дату» можно было бы выбрать несколько наборов за реальные сутки.
- **Часы вперёд.** Жёстко не блокируем: наказывать нечем, соревнования нет, backend отсутствует. Пользователь может пролистать несколько наборов подряд, но выигрывает только право быстрее остаться без контента. Серия считается по фактическим календарным датам назначений, так что пролистывание даёт формально непрерывную серию — это принятая цена отсутствия доверенного источника времени, и она никого, кроме самого пользователя, не касается.
- **Смена часового пояса.** Сдвиг границы суток на несколько часов допустим: единственное следствие — во сколько именно станет доступен следующий набор. Полёт через линию перемены дат в худшем случае откладывает следующий набор на сутки, но никогда не отменяет уже назначенный.
- `lastSeenDate` продолжает храниться для показа строки «Вчера день остался незавершённым» и для перепланирования напоминания.

### Перезапуск процесса и незавершённая сессия

- Всё состояние сессии выводится из базы: какие головоломки дня уже имеют `PuzzleAttempt`. В памяти хранится только текущий, ещё не проверенный порядок карточек.
- Текущий порядок сохраняется в `SavedStateHandle`, поэтому переживает поворот экрана и смерть процесса при восстановлении Activity. При холодном старте с нуля порядок сбрасывается на исходный перемешанный — это допустимо, потому что перестановки до проверки бесплатны.
- Перемешивание карточек детерминировано: `Random(seed = puzzleId.hashCode())`. Один и тот же стартовый порядок у всех пользователей и после перезапуска, никакой «удачной раздачи».
- При старте приложения:
  - назначения на сегодня нет, новый или отложенный набор доступен → `Home.Ready`;
  - назначение на сегодня есть, пройдено 0–2 задания → `Home.InProgress`, «Продолжить» открывает первую неотвеченную головоломку (при нуле попыток — первую в наборе);
  - пройдено 3 → `Home.Completed`;
  - новый набор сегодня не положен (часы переведены назад) → `Home.AwaitingNextDay`;
  - наборы пакета израсходованы → `Home.ContentExhausted`.

### Незавершённый вчерашний день

Доигрывать нельзя. При открытии приложения на следующий день:

- вчерашний день закрывается в архиве как «не завершён» с частичным баллом;
- **текущая серия обнуляется полностью**, лучшая серия сохраняется и продолжает показываться рядом. Никаких «заморозок», пропусков-исключений и восстановлений: решение принято окончательно (см. `PRODUCT.md`, раздел 3);
- на `Home` показывается одна нейтральная строка «Вчера день остался незавершённым» — без восклицательных знаков и без предложения что-то восстановить;
- сегодняшний день начинается обычным образом со **следующего** набора.

**Набор с хотя бы одной попыткой считается израсходованным.** Несыгранные головоломки из него не возвращаются и видны в архиве как «не сыграно». Это граница между «пропущенным» и «брошенным» днём: набор, по которому не сделано ни одной попытки, переносится на следующую дату (раздел «Перенос отложенного назначения»), а набор с первой же проверенной головоломкой — нет.

Альтернатива — переносить незавершённый набор на следующий день — рассмотрена и отклонена: она делает понятие «день» плавающим, ломает однозначность серии и позволяет накапливать долг из недоигранных наборов. Цена отклонения — до двух потерянных головоломок на каждый брошенный посреди дня набор; это редкий сценарий, и он не должен усложнять модель.

## 10. Доступность

### Альтернатива перетаскиванию

Перетаскивание — **не единственный** способ упорядочивания. У каждой карточки постоянно видны кнопки ↑ и ↓ (не скрыты за меню, не появляются только в режиме доступности): они полезны и зрячим пользователям на ходу.

- Кнопка ↑ у первой карточки и ↓ у последней — `disabled`, а не скрыты (иначе прыгает раскладка).
- Каждое перемещение сопровождается коротким `haptic` (если вибрация включена) и `announceForAccessibility`-сообщением вида «Эверест перемещён на позицию 2 из 4».
- Размер сенсорной цели кнопок — не менее 48×48 dp.

### Semantics для TalkBack

Каждая карточка получает:

- `contentDescription` вида «Позиция 2 из 4. Эверест» — позиция первой, потому что она меняется и её проговаривание важнее названия;
- на экране результата список читается как правильный порядок со значениями («Позиция 2 из 4. Эльбрус, 5642 метра»), а перепутанные пары озвучиваются отдельными строками ниже — так TalkBack-пользователь получает то же объяснение, что и зрячий, без опоры на цвет;
- пользовательские действия через `customActions`: «Переместить вверх», «Переместить вниз», «Переместить в начало», «Переместить в конец» — все четыре доступны в MVP, не как будущая доработка; это даёт TalkBack-пользователю тот же контроль, что и жест перетаскивания. Конкретной карточке предлагаются только действия, реально меняющие её позицию: на первой позиции отсутствуют «Переместить вверх» и «Переместить в начало», на последней — «Переместить вниз» и «Переместить в конец»;
- `liveRegion = Polite` у контейнера списка, чтобы изменения порядка озвучивались.

Заголовки экранов помечаются `semantics { heading() }`. Порядок фокуса — сверху вниз, кнопка «Проверить» последняя.

### Прочее

- Поддержка увеличенного шрифта до 200%: никаких фиксированных высот карточек, текст в `sp`, карточка растёт по содержимому. Проверяется на «Самый большой» размере шрифта системы.
- Тёмная тема — полноценная палитра, не инверсия. Контраст текста ≥ 4.5:1 в обеих темах.
- Edge-to-edge включён, все экраны учитывают `WindowInsets`: кнопка «Проверить» — над жестовой панелью, шапка — под статус-баром.
- `LocalAccessibilityManager` / настройка «Убрать анимацию»: анимации перестановки и появления результата сокращаются до мгновенных.
- Ландшафтная ориентация поддерживается адаптивно (список сужается, отступы растут); отдельный дизайн не делается.
- Ни одна информация не передаётся только цветом: совпадение позиции обозначается иконкой + текстом, а не только зелёным.

## 11. Ошибки и деградация

| Ситуация | Поведение |
| --- | --- |
| JSON контента не разбирается при старте | `Home.Error` с «Повторить». Логируем; поскольку контент встроен в APK, это означает баг сборки — валидация в CI должна такого не допускать |
| Отдельная головоломка невалидна | Не роняем день: `Puzzle.Error` + «Пропустить», 0 баллов, день завершается на оставшихся |
| База данных недоступна / повреждена | Показываем `Error` на Home. Fallback: пересоздание базы с потерей истории только по явному действию пользователя («Начать заново») — не автоматически |
| Разрешение на уведомления отозвано | Переключатель показывает выключенное состояние при следующем открытии настроек |
| Нет интернета | Не влияет ни на что: интернет приложению не нужен нигде |

## 12. Открытые места в этом документе

Помечены как решения по умолчанию, изменяемые до реализации: время напоминания по умолчанию (9:00), формат карточки шеринга (три строки по шесть символов), отсутствие сброса прогресса, момент фиксации назначения набора (нажатие «Играть», а не первое «Проверить»).

Визуальные решения в этом документе намеренно не приняты: они относятся к Design Gate.
