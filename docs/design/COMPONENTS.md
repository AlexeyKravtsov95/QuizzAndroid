# COMPONENTS.md — «По порядку!»

Design Gate, часть B1. Статус: черновик на утверждение. Инвентарь компонентов концепции D. Все токены — из `DESIGN_TOKENS.md`; ни одно значение здесь не вводится заново. Все состояния и переходы — из `UX_FLOW.md`; ни один компонент не добавляет продуктовую функцию, которой нет в этом документе.

Компоненты делятся на **основные** (проверяются на одном из четырёх базовых состояний B2 — Home `Ready`, Puzzle `Playing`, PuzzleResult, DayRecap — если появляются именно там, либо, если их реальное место появления лежит вне этой четвёрки, полноценным state sheet той же строгости) и **вспомогательные** (Archive, Settings и служебные состояния `Loading`/`Empty`/`Error` — описываются здесь отдельными state sheets, без требования отдельного макета-экрана) — деление и критерий взяты из `ARCHITECTURE.md`, раздел 11. Итоговый комплект — ровно 12 полноэкранных артбордов (4 состояния × 2 темы + 4 варианта при 200%). **Пять компонентов ниже — исключение по чисто географической причине** (их реальное место появления не входит в выбранную четвёрку B2, а не потому что они менее важны); см. раздел «Классификация» сразу после этого абзаца, где исключение объяснено и закрыто явно.

## Классификация: 12 артбордов B2 и state sheets

`ARCHITECTURE.md` (раздел 11) требует, чтобы каждый основной компонент был проверен способом, закреплённым за его реальным местом появления: компоненты четырёх базовых состояний (`Home.Ready`, `Puzzle.Playing`, `PuzzleResult`, `DayRecap`) проверяются на одном из 12 артбордов B2, а компоненты, чьё реальное место появления лежит вне этой четвёрки, — полноценным state sheet той же строгости. В перечне «основных» назван и «индикатор прогресса из трёх точек» (`ThreeStepProgress`) — но ни `Home.Ready`, ни `Puzzle.Playing`, ни `PuzzleResult`, ни `DayRecap` не показывают этот компонент: он живёт на `Home.InProgress` и в `Archive row` — ни то, ни другое не входит в выбранную четвёрку, и именно поэтому он проверяется state sheet, а не макетом. Это не продуктовое противоречие и не повод добавлять пятый макет — состав 12 артбордов B2 этим проходом не меняется. Это вопрос классификации: часть компонентов «основные» по функции, но их реальное появление приходится на состояния/экраны, которые в четвёрку B2 не попали. Ниже — окончательное, без вариантов, распределение.

| Компонент | Появляется на | Как проверяется в Design Gate |
| --- | --- | --- |
| `ThreeStepProgress` | `Home.InProgress`, `Archive row` — ни то, ни другое не входит в 4 артборда B2 | **Обязательный полноценный state sheet** (уже есть выше) — с той же строгостью, что макет: все комбинации `mode`/`completedCount` (`ActiveDay` 0–2, `ClosedDay` 0–3), оба места использования |
| `DragEducationHint` | `Puzzle.Playing`, но только при `hasSeenDragHint == false` — это не базовое состояние `Playing`, которое рисуется на артборде, а его одноразовый вариант | **State sheet первого использования** — базовый артборд `Puzzle.Playing` показывает экран без подсказки (обычное состояние), подсказка проверяется отдельным state sheet |
| `SourceRow` | Внутри `SourcesBlock` на `PuzzleResult`, но только в состоянии `expanded` — артборд `PuzzleResult` показывает `SourcesBlock` свёрнутым по умолчанию | **State sheet внутри `expanded SourcesBlock`** — все три состояния (`link`/`urlPlainText`/`referenceOnly`) проверяются там, не на основном артборде |
| `ShareCard` | Нигде как UI — это не Compose-компонент | **Невизуальная format specification** — категория «появляется на артборде» к нему неприменима по определению; проверяется как текстовая спецификация, не визуально |
| `NotificationOptInDialog` | `DayRecap`, но только один раз в жизни пользователя, поверх базового состояния экрана | **Modal state sheet** — базовый артборд `DayRecap` показывает экран без диалога; диалог проверяется отдельным state sheet |

Отдельно, шестым: `CategoryLabel` **проверяется на артбордах** (правый слот `AppTopBar` на `Puzzle`, строки `DayResultRow` на `DayRecap`) и потому в таблицу исключений не входит. Но артборды показывают одновременно только три категории из семи, а таблица иконок обязана быть проверена целиком, поэтому у компонента есть дополнительный state sheet `category-label` — секция со всеми семью пиктограммами рядом. Это **не** полноэкранный артборд и не замена проверке на макете: это проверка полноты набора, которую макет по своей природе дать не может.

Ни один из этих пяти компонентов не получает отдельный полноэкранный артборд сверх уже зафиксированных 12 — это и есть исправление классификации без изменения комплекта B2. Основные видимые компоненты каждого из четырёх выбранных состояний (`DailyIssuePanel`, `HomeHeader`, `PrimaryButton`, `OrderableCard`, `MoveButton`, `DragHandle`, `CategoryLabel`, `ScoreBadge`, `ScoringHint`, `InvertedPairRow`, `SourcesBlock` в свёрнутом виде, `ReportInaccuracyAction`, `DayResultRow`, `StreakRow`, `SecondaryButton`) по-прежнему обязаны встретиться на одном из четырёх макетов — это правило не ослаблено, оно просто не применяется буквально к компонентам, чьё естественное место — за пределами выбранной четвёрки.

## Основные компоненты

### AppTopBar

**Назначение.** Заголовок экрана + навигация назад, где применимо. Используется на `Puzzle`, `PuzzleResult`, **`DayRecap`**, `Archive`, `Settings`. На `Home` не используется — там заголовок продукта не является навигационным (см. `DailyIssuePanel`).

**Использование на `DayRecap` — окончательно, без вариантов.** `UX_FLOW.md` (раздел 1) требует у экрана `recap/{date}` заголовок «Сегодня» или дату; прежняя редакция этого раздела не включала `DayRecap` в перечень выше, и это был пробел в перечислении, а не отдельное решение. Пробел закрыт: заголовок `DayRecap` — это тот же `AppTopBar`, а не новый компонент.

| Вариант `DayRecap` | Заголовок | Leading-иконка «Назад» | Нижняя `PrimaryButton` | Куда ведёт выход |
| --- | --- | --- | --- | --- |
| Сегодняшний итог (`recap/today`, приход из `PuzzleResult(2)`) | «Сегодня» | **Отсутствует** | «Готово» | `Home` — либо `PrimaryButton`, либо системная кнопка «назад»; других выходов нет |
| Архивный итог (`recap/{date}`, приход из `Archive`) | Дата этого дня | Есть, ведёт в `Archive` | «Назад» | `Archive` |

Причина отсутствия leading-иконки на сегодняшнем итоге — навигационная, а не эстетическая: граф `dailySession` к этому моменту вычищен из бэкстека (`popUpTo("home")`, `UX_FLOW.md` раздел 1), возвращаться в задания нельзя, и кнопка «Назад» в шапке вела бы туда же, куда «Готово». Две кнопки с одним и тем же назначением — лишний фокус-стоп для TalkBack и лишняя цель для промаха. Системная кнопка «назад» при этом продолжает работать и ведёт на `Home`.

Артборды 07, 08 и 12 — вариант **сегодняшнего** итога.

**Анатомия.** [Кнопка назад (опционально)] — [Заголовок, `titleMedium`] — [опциональный правый слот: `CategoryLabel` на `Puzzle`].

**Правый слот и его перенос при недостатке ширины.** Правый слот занимает только `CategoryLabel` и только на `Puzzle`. Поведение зафиксировано, без вариантов:

- при достаточной ширине `CategoryLabel` находится в правом слоте, выровненная по правому краю контентной колонки, по вертикали — по центру шапки;
- если при текущей ширине и текущем масштабе шрифта заголовок и метка не помещаются в одну строку (проверяемое условие: `ширина заголовка + spacing.300 + ширина CategoryLabel > доступная ширина`, где доступная ширина считается после кнопки «Назад»), `CategoryLabel` **переносится на вторую строку** шапки, выровненная по левому краю заголовка; высота `AppTopBar` растёт на высоту метки плюс `spacing.200` сверху и снизу;
- кнопка «Назад» сохраняет `size.backButton` (48 × 48 dp) при любом переносе;
- `CategoryLabel` **не уменьшается** — ни кегль `labelMedium`, ни `icon.size.small`, ни внутренние отступы;
- сокращение любой сенсорной цели ради умещения запрещено; сжимается компоновка, а не цели;
- порядок фокуса TalkBack не зависит от переноса и всегда один: «Назад» → заголовок → категория.

Перенос проверен на артборде 10 (320 dp, 200%) — там метка уходит на вторую строку; на артбордах 03 и 04 (390 dp, 100%) она остаётся в правом слоте.

**Размеры.** Высота контейнера — `size.button.height` (56 dp) + верхний system inset (динамический, раздел 6.10 `DESIGN_TOKENS.md`). Кнопка назад — `size.backButton` (48 × 48 dp), визуальная иконка `icon.size.default` (24 dp), `icon.strokeWidth.default`.

**Токены.** `titleMedium`, `ColorScheme.onSurface` (заголовок и иконка), `spacing.margin.default`/`spacing.margin.compact` (горизонтальные поля).

**Состояния.** `default` (заголовок статичен). Кнопка назад присутствует на `Puzzle`, `PuzzleResult`, `Archive`, `Settings` и на **архивном** варианте `DayRecap`; отсутствует на **сегодняшнем** варианте `DayRecap` (см. таблицу выше) и на `Home`, где `AppTopBar` не используется вовсе.

**Интеракции.** Нажатие кнопки назад — системная навигация назад (`PuzzleEvent.BackPressed`/аналог для других экранов).

**Длинный текст.** Заголовок не переносится на второй смысл — если не помещается в одну строку (например, длинное название категории), переносится на вторую строку `titleMedium`, кнопка назад не сжимается.

**200%.** Контейнер растёт по высоте, если заголовок переносится; `size.backButton` — без изменений.

**320 dp.** `spacing.margin.compact` (16 dp) вместо `spacing.margin.default`.

**Темы.** `onSurface` на `surface` в обеих темах (13.75:1 / 14.08:1 — `DESIGN_TOKENS.md`, раздел 6.2).

**Accessibility.** Заголовок помечен `semantics { heading() }`. Кнопка назад имеет `contentDescription` = «Назад» и собственную сенсорную цель 48×48 dp, не пересекающуюся с заголовком. Порядок обхода TalkBack — «Назад» → заголовок → `CategoryLabel`, независимо от того, стоит метка в правом слоте или перенесена на вторую строку: визуальный перенос не меняет порядок чтения.

**TalkBack-текст.** Кнопка назад: «Назад, кнопка».

**Ошибки, которые нельзя допускать.** Уменьшение кнопки назад ради умещения длинного заголовка; уменьшение `CategoryLabel` (кегля, иконки или отступов) вместо переноса её на вторую строку; leading-иконка «Назад» на сегодняшнем итоге `DayRecap`; отсутствие кнопки «Назад» на архивном итоге; отсутствие `heading()` на заголовке; изобретение отдельного компонента-заголовка для `DayRecap` вместо переиспользования `AppTopBar`.

### HomeHeader

**Назначение.** Верхняя часть экрана Home — функциональный аналог `AppTopBar` там, где `AppTopBar` не используется (см. «Назначение» `AppTopBar`). Единственный компонент Home, к которому применяется верхний системный inset (`UI_REVIEW_CHECKLIST.md`, «Edge-to-edge»). Присутствует во всех состояниях Home без исключения, включая `FirstRun`, `ContentExhausted`, `Loading` и `Error`.

**Исключение из логики `AppTopBar`.** Мастхед `HomeHeader` — фирменная редакционная подпись продукта в serif (роль `Masthead`), а не обычная навигационная шапка экрана: в отличие от `titleMedium`-заголовков `AppTopBar` («Задание 1 из 3», «Архив», «Настройки»), которые называют текущий экран, мастхед называет продукт целиком и не меняется между состояниями Home. Это осознанное и единственное подобное исключение — ни один другой заголовок в системе не получает serif или роль `Masthead`.

В `Home.Loading` — мастхед и дата отрисованы как обычно (статичный текст, не требует данных), иконка архива скрыта до момента чтения прогресса (см. таблицу видимости ниже), под шапкой показывается `Loading skeleton` (state sheet ниже) вместо `DailyIssuePanel`. В `Home.Error` — мастхед и дата также отрисованы как обычно; ниже — вариант `Error.retryable` («Не удалось загрузить задания» + «Повторить», см. state sheet `Error` ниже), а `Statistics block` показывается под ним дополнительно **только если** локальный прогресс читается и `completedDayCount > 0` (`UX_FLOW.md`, раздел 11: «серия и архив показываются, если прогресс читается»); если прогресс не читается — под текстом ошибки нет ничего, кроме `PrimaryButton` «Повторить». `DailyIssuePanel` в `Error` не показывается ни в каком виде — только `Statistics block`, никогда оба и никогда как взаимозаменяемая запись «одно или другое».

**Анатомия.** Мастхед «ПО ПОРЯДКУ!» слева → hairline (`outlineVariant`, `size.divider.thickness`) под мастхедом на всю ширину → дата (`Metadata`, mono) под hairline слева → иконки архива и настроек справа от мастхеда, на одной визуальной строке с ним.

Мастхед — именованная проектная роль `Masthead` (`DESIGN_TOKENS.md`, раздел 6.4: Noto Serif SemiBold 600, 14/20 sp, `letterSpacing` = 2 sp, обязательный `textTransform = uppercase`), а не `titleLarge` с переопределением на месте. Значение трекинга и регистра приходит из токена `Masthead` целиком — компонент не задаёт `letterSpacing = 2.sp` литералом.

**Размеры.** Ширина — контентная колонка. Высота — по содержимому (мастхед + hairline + дата) плюс верхний system inset, применённый к контейнеру целиком.

**Токены.** `Masthead` (мастхед), `Metadata` (дата), `outlineVariant`/`size.divider.thickness` (hairline), `ColorScheme.onSurface` (мастхед и дата), `size.headerIcon`/`icon.size.default` (иконки архива и настроек).

**Видимость иконки «Архив» — по данным, не по названию состояния.** Правило одно и то же во всех состояниях Home и формулируется через `completedDayCount` (число завершённых дней), а не через то, как называется текущее `HomeUiState`:

| Условие | Иконка «Архив» | Иконка «Настройки» |
| --- | --- | --- |
| `completedDayCount > 0`, прогресс прочитан | Видна | Видна |
| `completedDayCount == 0`, прогресс прочитан (соответствует `FirstRun`) | Скрыта | Видна |
| Прогресс ещё не прочитан (`Home.Loading`) | Скрыта — до момента чтения прогресса, чтобы иконка не появлялась/не исчезала повторно («не мигала») сразу после отрисовки | Видна |
| Прогресс не удалось прочитать (`Home.Error`), `completedDayCount` неизвестен | Скрыта | Видна |
| `Home.Error`, но прогресс успешно прочитан и `completedDayCount > 0` | Видна | Видна |

Настройки видны всегда, при любом условии — единственная переменная видимость в `HomeHeader` — у иконки архива. Компонент не хранит и не проверяет имя состояния экрана — он получает уже вычисленный булев параметр (например, `isArchiveVisible: Boolean`), а вычисление этого параметра по `completedDayCount` и факту чтения прогресса — ответственность слоя данных, не UI.

В состоянии `FirstRun` под мастхедом дополнительно показывается одноразовая поясняющая строка (`bodyMedium`) «Три задания в день. Расставьте карточки в правильном порядке» (`UX_FLOW.md`, раздел 2) — она принадлежит `HomeHeader`, не `DailyIssuePanel`.

**Интеракции.** Нажатие иконки архива/настроек — переход на соответствующий экран.

**Длинный текст.** Не применимо — мастхед и дата фиксированного, короткого текста.

**Адаптивное поведение при недостатке ширины (320 dp и/или 200%).** Если мастхед и обе иконки не помещаются в одну визуальную строку, порядок разрешения конфликта фиксирован: мастхед остаётся первой строкой на всю ширину; иконки архива и настроек переносятся на отдельную строку под мастхедом, выровненную по правому краю. Touch targets иконок (`size.headerIcon`, 48 × 48 dp) не уменьшаются ни при каком переносе — сжимается компоновка (перенос на новую строку), а не сами сенсорные цели. Дата при этом остаётся на своей строке под hairline независимо от того, перенеслись иконки или нет.

**200%.** Мастхед растёт по кеглю (растёт `Masthead`, как и любая другая роль, вместе с системным масштабом); при нехватке ширины применяется правило адаптивного переноса выше. Дата растёт по кеглю и при необходимости переносится на отдельную строку под мастхедом независимо от иконок.

**320 dp.** `spacing.margin.compact` (16 dp) вместо `spacing.margin.default`.

**Темы.** `onSurface` на `surface` в обеих темах (13.75:1 / 14.08:1).

**Accessibility.** Мастхед помечен `semantics { heading() }`. Иконки — независимые сенсорные цели 48 × 48 dp, не пересекающиеся (см. «Touch targets — сводная проверка»).

**TalkBack-текст.** «Архив, кнопка» / «Настройки, кнопка».

**Ошибки, которые нельзя допускать.** Вычисление видимости иконки архива по имени состояния экрана (`if (state is HomeUiState.FirstRun)`) вместо вычисления по данным (`completedDayCount > 0` и факту чтения прогресса) — это два разных источника истины, и они обязаны совпадать всегда, что проще гарантировать одним вычислением, а не дублированием условия по состояниям; показ архива до того, как прогресс прочитан (мигание иконки при старте); показ категории дня в этом компоненте (в `HomeHeader` категории никогда не было и не будет — она вообще не раскрывается на Home); дублирование даты внутри `DailyIssuePanel` (дата принадлежит только `HomeHeader`); литеральный `letterSpacing = 2.sp` в коде компонента вместо ссылки на токен `Masthead`; уменьшение `size.headerIcon` при переносе иконок на вторую строку.

### DailyIssuePanel

**Назначение.** Композитный компонент, объединяющий номер дня и относящееся к нему содержимое Home в одну редакционную единицу (`HYBRID.md`, раздел 5). Присутствует в состояниях `Ready`/`InProgress`/`Completed`/`AwaitingNextDay`/`FirstRun`, в каждом — со своим содержимым (см. таблицу ниже). **Не показывается вовсе** в `ContentExhausted` и в `Error` (см. state sheets ниже) — там либо номера текущего дня не существует по определению состояния, либо экран показывает только `Statistics block`, а не этот компонент.

Дата не дублируется внутри `DailyIssuePanel` ни в одном варианте — она принадлежит `HomeHeader` и показывается один раз для всего экрана.

**Содержимое по состояниям — точная таблица.** Предыдущая редакция ошибочно описывала содержимое `Ready` как общее для всех состояний кроме `firstRun`; это неверно и исправлено здесь однозначно. Запись вида «`DailyIssuePanel`/`StatisticsBlock`» как взаимозаменяемая альтернатива не используется — у каждого состояния ровно один вариант.

| Состояние | Содержимое `DailyIssuePanel` | Источник (`UX_FLOW.md`) |
| --- | --- | --- |
| `FirstRun` | Номер доступного дня (`IssueLabel` «ВЫПУСК» + `IssueNumber`, обычно «День 1») + одна поясняющая строка `bodyMedium` «Задание дня · 3 головоломки · 2–4 минуты». Статистики нет как элемента (не нули) | Раздел 2: «Карточка дня + одна поясняющая строка, статистика скрыта» |
| `Ready` | Номер дня (`IssueLabel` + `IssueNumber`), серия, лучший день, сыграно дней — три строки статистики | Раздел 3, строка `Ready` |
| `InProgress` | Номер дня, текст «Задание N из 3», видимый `ThreeStepProgress`. Текущий счёт и итоговые баллы **скрыты** — ни промежуточного, ни какого-либо числового результата не показывается | Раздел 3, строка `InProgress`: «„Задание 2 из 3", прогресс-индикатор из трёх точек, текущий счёт скрыт» |
| `Completed` | Номер дня, «Сегодня: N из 18», серия, «Следующее задание — через ЧЧ:ММ» | Раздел 3, строка `Completed` |
| `AwaitingNextDay` | Номер **последнего завершённого** дня (не увеличивается), «Итог: N из 18», «Следующее задание — завтра» | Раздел 3, строка `AwaitingNextDay` |
| `ContentExhausted` | `DailyIssuePanel` **отсутствует** — не показывается ни в какой форме (см. state sheet `ContentExhausted`) | Раздел 3, строка `ContentExhausted` |
| `Error` | `DailyIssuePanel` **отсутствует**; если прогресс читается, показывается только `Statistics block` (не `DailyIssuePanel` в урезанном виде) | Раздел 11: «серия и архив показываются, если прогресс читается» |

Анатомия по вариантам:

**Полная форма (`Ready`/`Completed`/`AwaitingNextDay`).** Вертикальная `spine` (сплошная заливка `primary`, ширина `spacing.spine.width`) слева → отступ `spacing.spine.contentIndent` → блок «День»: метка `IssueLabel` («ВЫПУСК», mono, цвет `tertiary`) над `IssueNumber` (например, «День 24») → hairline (`outlineVariant`, `size.divider.thickness`) → содержимое состояния (три строки статистики для `Ready`; «Сегодня: N из 18» + серия + «Следующее задание — через ЧЧ:ММ» для `Completed`; «Итог: N из 18» + «Следующее задание — завтра» для `AwaitingNextDay`, метки строк — `CapsLabel`, sans, значения — `labelMedium`) → закрывающая hairline-линия перед `PrimaryButton` экрана.

**Вариант `InProgress`.** Тот же `spine` и блок «День», что в полной форме → hairline → текст «Задание N из 3» (`bodyLarge`) + `ThreeStepProgress` под ним → закрывающая hairline перед `PrimaryButton` «Продолжить». Ни счёта, ни баллов в этом варианте нет ни в каком виде — ни промежуточных, ни скрытых-но-отрендеренных.

**Вариант `firstRun`.** Тот же `spine`, тот же блок «День» (`IssueLabel` «ВЫПУСК» над `IssueNumber` с номером первого доступного набора, обычно «День 1») → hairline → **вместо строк статистики** одна поясняющая строка `bodyMedium`: «Задание дня · 3 головоломки · 2–4 минуты» (`UX_FLOW.md`, раздел 2, текст карточки задания дня) → закрывающая hairline перед `PrimaryButton` «Начать». Серия, лучший день и число сыгранных дней в этом варианте **отсутствуют как элементы**, а не показаны нулями — нулевые значения выглядели бы как поражение (`UX_FLOW.md`, раздел 2). Карточка дня при этом не убирается целиком: spine-композиция и номер доступного дня остаются на месте.

**Размеры.** Ширина — на всю доступную контентную колонку. Высота — не фиксирована, растёт по содержимому (минимум = высота блока «День» + hairline + содержимое состояния, каждая строка ≥ `spacing.900` = 48 dp по внутреннему тексту + отступам).

**Токены.** `IssueNumber`, `IssueLabel`, `CapsLabel`, `labelMedium`, `bodyLarge`, `bodyMedium`, `ThreeStepProgress`, `outlineVariant`, `ColorScheme.primary` (spine), `ColorScheme.tertiary` (метка «ВЫПУСК»), `spacing.spine.width`, `spacing.spine.contentIndent`, `spacing.100` (внутри строки статистики).

**Интеракции.** Нет собственных — панель не кликабельна целиком (действие — отдельная `PrimaryButton` под ней).

**Длинный текст.** Ни одно значение статистики не может стать длиннее ширины колонки при русской локализации (максимум — «Сыграно дней» + трёхзначное число); если когда-либо потребуется больше — перенос значения на новую строку внутри своей строки статистики, метка не сокращается.

**200%.** Каждая строка растёт по высоте; `spacing.spine.width` (3 dp) — константа, spine удлиняется вместе с блоком, не становится толще.

**320 dp.** `spacing.spine.contentIndent` не уменьшается (это отступ текста от spine, а не отступ экрана) — сокращается только `spacing.margin.compact` снаружи всей панели.

**Темы.** Spine — `primary` (light `#2C4A3E` / dark `#3E6350`); метка «ВЫПУСК» — `tertiary`; значения — `onSurface`; метки статистики — `onSurfaceVariant`.

**Accessibility.** Компонент — один `semantics`-контейнер, содержимое `contentDescription` соответствует содержимому состояния из таблицы выше, не более и не менее: «Выпуск 24. Серия 6 дней. Лучший день 17 из 18. Сыграно дней 23» (`Ready`); «Выпуск 24. Задание 2 из 3» (`InProgress` — без чисел счёта, которых нет на экране); «Выпуск 24. Сегодня 15 из 18. Серия 6 дней. Следующее задание через 14:30» (`Completed`); «Выпуск 23. Итог 15 из 18. Следующее задание завтра» (`AwaitingNextDay`); «Выпуск 1. Задание дня. 3 головоломки, 2–4 минуты» (`FirstRun`) — не четыре/пять отдельных фокус-стопов: иначе TalkBack-пользователь проходит Home дольше зрячего без причины.

**TalkBack-текст.** См. выше — один составной `contentDescription`.

**Ошибки, которые нельзя допускать.** Раздельные карточки/поверхности под номером дня и статистикой (это откат к проблеме исходной концепции A, которую D решает слиянием — `HYBRID.md`, раздел 5); показ категории дня внутри этого компонента ни при каких условиях; показ содержимого одного состояния в другом (например, счёта или трёх строк статистики в `InProgress`, где по `UX_FLOW.md` показывается только «Задание N из 3» + `ThreeStepProgress`, а счёт скрыт); показ `DailyIssuePanel` (в любой форме) в `ContentExhausted` или `Error`.

### PrimaryButton

**Назначение.** Единственное основное действие экрана: «Играть»/«Продолжить»/«Посмотреть итог» (Home), «Проверить» (Puzzle), «Дальше»/«К итогу дня» (PuzzleResult), «Готово» (DayRecap).

**Анатомия.** Контейнер на всю ширину контентной колонки, текст `labelLarge` по центру.

**Размеры.** `size.button.height` = 56 dp минимум, `shape.small` (8 dp).

**Токены.** `ColorScheme.primary` (заливка), `ColorScheme.onPrimary` (текст), `labelLarge`, `shape.small`, `motion.duration.short` + `opacity.pressedStateLayer` (нажатие).

**Состояния.** `default`, `pressed` (state layer `opacity.pressedStateLayer` поверх `onPrimary`), `disabled`.

**`disabled` — используется в MVP, ровно в трёх местах:**

1. `Puzzle.Loading` — кнопка «Проверить» в дереве, но недоступна, пока головоломка не загружена (`ARCHITECTURE.md`, `PuzzleUiState.Loading`);
2. первые `dragHint.submitLockDuration` (600 мс) после появления `DragEducationHint` на первой головоломке дня (`UX_FLOW.md`, раздел 2);
3. во время `Submitting`, если кнопка остаётся в дереве, а не заменяется индикатором загрузки (решение конкретной реализации — оба варианта допустимы, но если кнопка осталась в дереве, она обязана быть в состоянии `disabled`, а не в `default` с блокировкой обработчика нажатия только на уровне ViewModel).

**Визуальный вид `disabled` — однозначный, без вариантов:**

- фон прозрачный — заливки `primary` и `surfaceContainer` нет, ни одна из них не используется как фон `disabled`-состояния;
- вместо заливки — приглушённая обводка `outline` при `opacity.disabledContent` (38%);
- текст `labelLarge` — `onSurface` при `opacity.disabledContent` (38%), не `onPrimary`;
- обязательная disabled-семантика (`Modifier.semantics { disabled() }` / роль кнопки с флагом недоступности для TalkBack и switch access);
- состояние отличается от `enabled` не только оттенком — заливка присутствует/отсутствует (форма меняется, не только цвет), что соответствует общему правилу «disabled различим не только цветом» (`DESIGN_PRINCIPLES.md`, раздел 7).

Тот же визуальный паттерн (нет заливки + приглушённая обводка + `opacity.disabledContent`) уже используется для disabled-`MoveButton` — `PrimaryButton.disabled` следует ему, а не изобретает отдельный вид для кнопок.

**Интеракции.** Однократное нажатие. `ViewModel` принимает `Submit` только из состояния `Playing` и немедленно переводит экран в `Submitting` (`ARCHITECTURE.md`) — кнопка остаётся `disabled` **всё время**, пока `UiState` находится в `Submitting`, а не в течение фиксированного окна вроде `motion.duration.short`. `motion.duration.short` здесь не при чём: это токен визуального перехода, а не длительность блокировки повторного нажатия — блокировка определяется состоянием, а не таймером.

**Длинный текст.** Не актуально — все существующие подписи однословные/двухсловные и короче ширины кнопки на 320 dp с большим запасом; если бы не помещалось — перенос на вторую строку, кнопка растёт по высоте.

**200%.** Растёт по высоте при переносе текста, никогда не выходит за пределы `spacing.margin.*` по бокам.

**320 dp.** Без изменений, кроме внешних полей экрана.

**Темы.** `primary`/`onPrimary` пары, обе прошли 4.5:1 (раздел 6.2 `DESIGN_TOKENS.md`).

**Accessibility.** Роль `Button`, `contentDescription` = видимый текст (кнопка самодостаточна по тексту, дополнительного описания не требует).

**TalkBack-текст.** Совпадает с видимым текстом кнопки.

**Ошибки, которые нельзя допускать.** Использование `tertiary` (терракота) как заливки; уменьшение высоты ниже `size.touchTarget.min` (48 dp) ни при каких условиях.

### SecondaryButton

**Назначение.** Второстепенное действие, не забирающее внимание у `PrimaryButton`. Используется ровно в трёх местах:

1. «Пропустить» на `Puzzle.Error` (`UX_FLOW.md`, раздел 4: «Задание недоступно» + «Пропустить»; пропущенная головоломка засчитывается как 0 баллов, день можно завершить);
2. «Поделиться» на `DayRecap` (второстепенна относительно «Готово»/«Назад» — раздел 3 `DESIGN_PRINCIPLES.md` ставит её после `StreakRow`, перед итоговой кнопкой);
3. «Не нужно» в `NotificationOptInDialog` (второстепенна относительно «Да, в 9:00»).

**Анатомия.** Контейнер той же ширины/высоты, что `PrimaryButton`, но с обводкой вместо заливки.

**Размеры.** `size.button.height` = 56 dp минимум, `shape.small` (8 dp).

**Токены.** `ColorScheme.outline` (обводка), `ColorScheme.onSurface` (текст), `labelLarge`.

**Состояния.** `default`, `pressed` (`opacity.pressedStateLayer` поверх `onSurface`), `disabled` (обводка `outline` при `opacity.disabledContent`, текст та же).

**Интеракции.** Аналогично `PrimaryButton`.

**Длинный текст / 200% / 320 dp.** Идентично `PrimaryButton`.

**Темы.** `outline` против `surface` — 3.20:1 (light) / 4.60:1 (dark), проходит требование к значимым границам (≥ 3:1).

**Accessibility.** Роль `Button`, поведение аналогично `PrimaryButton`.

**Ошибки, которые нельзя допускать.** Заливка `tertiary` или `secondary` вместо прозрачного фона с обводкой — `SecondaryButton` в системе всегда outlined, не tonal-filled (единственный «tonal»-подобный элемент системы — `primaryContainer`-заливка `CategoryLabel` и `MoveButton`, у кнопок такого варианта нет).

### CategoryLabel

**Назначение.** Небольшая каталожная метка категории. Используется ровно в двух местах: на `Puzzle` (в `AppTopBar`) и внутри `DayResultRow` на `DayRecap`. На `PuzzleResult` не показывается и не дублируется — `UX_FLOW.md` (раздел 5) не включает категорию в состав этого экрана. Категория не раскрывается на `Home` ни в каком виде.

**Анатомия.** [Пиктограмма категории, `icon.size.small`] + [Текст `labelMedium`], в контейнере `shape.extraSmall`.

#### Таблица иконок категорий — окончательная

Семь значений enum `category` из `CONTENT_MODEL.md`, у каждого своя пиктограмма. Все семь — из **одной** системы **Material Symbols Outlined** (`github.com/google/material-design-icons`, Apache License 2.0), взятые с одинаковыми значениями осей: `FILL 0`, `GRAD 0`, `opsz 20`, `wght 600`. Одинаковые оси и есть гарантия единого визуального веса набора — это свойство построения, а не результат подбора на глаз.

| `category` | Название в UI | Material Symbol | Почему именно этот символ |
| --- | --- | --- | --- |
| `geography` | География | `public` | Земной шар с меридианами — общепринятая пиктограмма географии |
| `history` | История | `account_balance` | Классический портик, устойчивый знак древности. `history_edu` (перо и свиток) отклонён: на 16 dp сливается в пятно |
| `science` | Наука | `science` | Колба — символ, названный в системе именно `science` |
| `nature` | Природа | `park` | Дерево. `forest` (три дерева) отклонён: на 16 dp темнеет в пятно |
| `culture` | Культура | `palette` | Палитра — искусство и культура. `theater_comedy` отклонён: две маски на 16 dp неразличимы |
| `russia` | Россия | `flag` | Флаг как знак страны; не пересекается с глобусом географии |
| `mixed` | Смешанное | `category` | Набор разных фигур — «несколько категорий сразу» |

Требования к этому набору, все проверяемые:

- **одно семейство** — Material Symbols Outlined, ни одной иконки из другого набора и ни одной нарисованной вручную;
- **единый визуальный вес** — одинаковые `FILL`/`GRAD`/`opsz`/`wght` у всех семи;
- **размер** — `icon.size.small` (16 dp), тот же токен, что уже действовал для этого компонента;
- **толщина линии** — `wght 600` при `opsz 20` даёт штрих 2.45/24 сетки, то есть **1.63 dp** после масштабирования 24-юнитовой коробки до 16 dp. Это `icon.strokeWidth.small` (1.6 dp) из `DESIGN_TOKENS.md`, раздел 6.5, измеренный на отрисованном контуре, а не принятый по аналогии;
- **читаемость при 16 dp** — проверена на state sheet `category-label` (все семь рядом в рабочем размере и в увеличении для разбора);
- **иконка всегда с названием категории** — ни один экран не показывает пиктограмму без текста;
- **никаких эмодзи** — единственное исключение из запрета на эмодзи в продукте относится к текстовому payload `ShareCard` и к иконкам категорий отношения не имеет;
- **в SVG это `path`, а не иконочный шрифт** — ни один глиф не адресуется кодом символа; геометрия семи путей зафиксирована в `tools/design-b2/category_icons.py`;
- **иконка горы не используется ни для одной категории.** Прежняя ревизия артбордов ставила одну и ту же гору у «Географии», «Истории» и «Науки» — это семантически неверно и исправлено этим проходом.

Изменение любой строки таблицы — правка этого документа, а не генератора артбордов.

**Размеры.** `size.categoryLabel.minHeight` = 26 dp — это **минимальная**, не фиксированная высота (внутренний отступ вокруг `labelMedium`, 13 sp текста); ширина — по содержимому.

**Токены.** `ColorScheme.primaryContainer` (фон), `ColorScheme.onPrimaryContainer` (иконка и текст), `labelMedium`, `shape.extraSmall`, `icon.size.small`, `size.categoryLabel.minHeight`.

**Состояния.** Единственное — `default` (категория не переключается, не нажимается).

**Интеракции.** Нет — не интерактивный элемент.

**Длинный текст.** Самое длинное значение `category` в `CONTENT_MODEL.md` (`history`, `geography`, `science`, `nature`, `culture`, `russia`, `mixed` → «История», «География», «Наука», «Природа», «Культура», «Россия», «Смешанное») — «Смешанное» (9 символов) длиннее «География» (9 символов, равны) — контейнер рассчитан по ширине содержимого, не имеет фиксированной максимальной ширины, поэтому перенос не требуется ни для одного значения enum.

**200%.** Контейнер растёт вместе с текстом. Иконка остаётся `icon.size.small` (16 dp) — размер в dp не масштабируется системной настройкой шрифта, и это требование чек-листа («иконки — размер не изменился относительно 100%»), а не упущение: при 200% пиктограмма выглядит меньше относительно текста, и так и должно быть. Радиус контейнера остаётся `shape.extraSmall` (4 dp) — радиусы тоже в dp и при 200% не растут.

**320 dp.** Без изменений — компонент компактный по своей природе.

**Темы.** `primaryContainer`/`onPrimaryContainer` — 7.89:1 (light) / 9.41:1 (dark).

**Accessibility.** `contentDescription` = «Категория: {название}» (иконка помечена как декоративная внутри составного описания — не дублирует текст отдельным фокус-стопом).

**Ошибки, которые нельзя допускать.** Показ на `Home`; показ только иконкой без текста; использование `tertiary` вместо `primaryContainer` (закрепляет категорию за «интерактивным» зелёным семейством, а не за терракотовым акцентом — категория не является действием); одна и та же пиктограмма у двух и более категорий; пиктограмма не из Material Symbols Outlined или с другими значениями осей, чем у остальных шести; рост радиуса `shape.extraSmall` или уменьшение `icon.size.small` при 200%.

### OrderableCard

Самый рискованный компонент системы — описан подробно, состояние за состоянием.

**Назначение.** Единица упорядочивания на `Puzzle`; в режиме только для чтения — единица показа правильного порядка на `PuzzleResult`.

**Анатомия (слева направо).**

1. **Индексная зона** (`size.orderableCard.indexZoneWidth` = 56 dp): номер `CardIndex` («№1»…«№4») сверху, `DragHandle` (сетка точек) снизу; отделена от центральной зоны вертикальной hairline-линией (`outlineVariant`, `size.divider.thickness`).
2. **Центральная зона** (гибкая ширина = вся оставшаяся ширина минус индексная зона и зона кнопок): название (`titleLarge`, serif) + уточняющая строка (`bodyMedium`, sans, `onSurfaceVariant`).
3. **Зона управления** (48 dp ширина + внутренние отступы): `MoveButton` вверх и `MoveButton` вниз, вертикальной парой.

Форма контейнера — `OrderableCardCutCorner` (раздел 6.6 `DESIGN_TOKENS.md`): `shape.medium` на трёх углах, диагональный срез `size.cutCorner` на верхнем правом.

**Размеры.** `size.orderableCard.minHeight` = 112 dp минимум, ширина — вся контентная колонка.

**Токены.** `ColorScheme.surfaceContainerLow` (заливка), тонкая обводка `outlineVariant` толщиной `size.divider.thickness` (1 dp — обеспечивает «слегка выраженную» поверхность без появления второй, более тёмной по смыслу роли), `titleLarge`, `bodyMedium`, `CardIndex`, `OrderableCardCutCorner`, `size.moveButton`.

#### Состояния

| Состояние | Визуальное отличие | Токены |
| --- | --- | --- |
| `default` | Заливка `surfaceContainerLow`, `elevation.resting` (0 dp) | Как в анатомии |
| `dragging` | `elevation.dragged` (6 dp, настоящая тень), дополнительный `opacity.dragStateLayer` (16% `primary`) поверх заливки, масштаб не меняется | `elevation.dragged`, `opacity.dragStateLayer`, `motion.duration.medium` на переход |
| `disabled movement` (карточка на первой или последней позиции — двигается только в одну сторону) | Одна из двух `MoveButton` в состоянии disabled (см. state sheet `MoveButton` ниже); сама карточка визуально не отличается от `default` | — |
| `correct result` (на `PuzzleResult`, карточка стоит на верной относительной позиции) | Только для чтения: `MoveButton` и `DragHandle` не отображаются вовсе (не просто disabled — их нет в дереве, экономит фокус-стопы для TalkBack); вместо `CardIndex` — итоговая позиция; добавляется `displayValue` карточки (например, «5642 м») строкой `bodyMedium` | Без цветового выделения «правильности» — она не самостоятельное состояние по цвету, читается из контекста экрана результата |
| `participates in inverted pair` (на `PuzzleResult`) | То же read-only анатомическое упрощение, что и «correct result»; сама карточка не подсвечивается цветом — перепутанная пара называется отдельной строкой `InvertedPairRow` под списком, использующей `tertiary` (терракота), а не заливкой самой карточки | `InvertedPairRow`, `ColorScheme.tertiary` |
| `already submitted / read-only` (общий случай PuzzleResult, объединяет два состояния выше) | `DragHandle` и оба `MoveButton` отсутствуют в дереве; карточка не реагирует на нажатие | — |

**Центральная зона не интерактивна.** Нажатие на карточку вне ручки перетаскивания и вне `MoveButton` **ничего не делает** — ни перестановки, ни навигации, ни какой-либо другой реакции за этим не следует. Соответственно, у неё нет собственного `pressed`-состояния: никакого ripple, `state layer` или иного визуального отклика на нажатие в этой зоне не показывается. Единственные интерактивные зоны карточки — `DragHandle` и два `MoveButton`; только они дают тактильный/визуальный отклик на нажатие.

**Правило про цвет для «correct»/«inverted».** Ни заливка, ни обводка карточки не меняются в зависимости от того, правильная позиция или перепутанная — единственный носитель этого различия — текст (`InvertedPairRow` перечисляет только перепутанные пары; всё, что не названо, подразумевается верным) и порядок отображения, что прямо соответствует правилу «цвет не единственный носитель состояния» (`DESIGN_PRINCIPLES.md`, раздел 7) и формулировке `UX_FLOW.md` (раздел 5: «Перепутанные пары оформляются приглушённым терракотовым, а не сигнальным красным» — сам терракотовый цвет здесь на **тексте строки `InvertedPairRow`**, не на карточке).

**Длинное название.** Проверено на «Аргентина» / «Альпы, Франция и Италия» (самая длинная уточняющая строка примера в `concept-d.svg`) — переносится на вторую строку в пределах центральной зоны, карточка растёт по высоте от `size.orderableCard.minHeight`; расстояние до `MoveButton`-колонки не сокращается ни при каком переносе (зафиксировано визуальной проверкой борда).

**Длинная уточняющая строка.** Аналогично названию — `bodyMedium` переносится, не обрезается эллипсисом.

**320 dp.** Индексная зона (56 dp), зона кнопок (48 dp + отступы) и срез угла (18 dp) — без изменений; сжимается только центральная зона, вызывая более ранний перенос названия/подстроки. Доказано стресс-примером `concept-d.svg`.

**200%.** Название `titleLarge` растёт до 40 sp, может занять 2–3 строки — карточка растёт по высоте без верхнего предела. `CardIndex`, `DragHandle`, `MoveButton` — без изменений размера (растёт только `sp`-текст внутри `CardIndex`, но зона, в которую он вписан, — фиксированной ширины 56 dp; если номер `№1` при 200% визуально не помещается в 56 dp по ширине шрифта, используется перенос номера на вторую строку внутри индексной зоны — зона не расширяется вбок за счёт центральной колонки).

**Единственная линия срезанного угла.** Только верхний правый угол; остальные три — `shape.medium` (12 dp), не срезаны, не заострены.

**Текущий номер позиции.** `CardIndex` — это **не постоянный ID карточки**, а текущая позиция в списке (`position: Int`, 1..4 из `CardUi.position` в `ARCHITECTURE.md`). При перестановке (кнопкой или перетаскиванием) значение `CardIndex` немедленно обновляется у всех карточек, чья позиция изменилась — синхронно с layout-анимацией перестановки (`motion.duration.long`), без отдельной задержки или анимации самого числа (число просто меняется на новое в момент, когда карточка достигает новой позиции).

**Индексная зона.** См. анатомию — фиксированная левая колонка 56 dp, номер сверху, ручка снизу, разделены визуально позицией (не отдельной линией внутри зоны).

**Ручка (`DragHandle`).** Зона захвата 48 × 48 dp (`size.dragHandle.touchTarget`), визуальный индикатор — сетка точек `icon.size.dragHandleGlyph` (16 × 24 dp, 2 колонки × 3 ряда), центрирована внутри зоны захвата. Начинает перетаскивание без долгого нажатия — захват сразу по касанию за эту зону (`UX_FLOW.md`, раздел 10: «Захват без длинного нажатия — за ручку»).

**Кнопки `MoveButton` (48 × 48 dp каждая).** См. отдельный state sheet ниже.

**Правило естественного переноса.** Ни при каких обстоятельствах в название или уточняющую строку карточки не вставляется ручной дефис для управления переносом — перенос выполняется механизмом Compose (`Hyphens.Auto` или перенос по пробелу), пример «Кили-манд-жаро» на стресс-борде `concept-d.svg` иллюстрирует *результат автоматического* переноса при экстремальной ширине, а не образец готового текста.

**TalkBack custom actions.** У каждой карточки — все четыре `customActions` в MVP, не как доработка будущих этапов: «Переместить выше», «Переместить ниже», «Переместить в начало», «Переместить в конец» (`PuzzleEvent.MoveToTop`/`MoveToBottom`, `ARCHITECTURE.md`). Действие, которое не изменило бы позицию карточки, пользователю не предлагается: у карточки на первой позиции нет «Переместить выше»/«Переместить в начало», у карточки на последней позиции нет «Переместить ниже»/«Переместить в конец» — та же логика, что и у `MoveButton.disabled`, только выражена не видимой disabled-кнопкой, а отсутствием соответствующего пункта в списке `customActions`. После срабатывания действия — `announceForAccessibility` вида «Эверест перемещён на позицию 2 из 4» (шаблон из `UX_FLOW.md`, раздел 10, переносится без изменений).

**Ошибки, которые нельзя допускать.**

- Применение `OrderableCardCutCorner` к карточке в read-only состоянии по-другому, чем в интерактивном — форма одна и та же во всех состояниях, кроме отсутствия `DragHandle`/`MoveButton` в дереве.
- Окрашивание всей карточки в `tertiary`/`error` при перепутанной паре.
- `CardIndex`, трактуемый в коде как стабильный идентификатор данных (например, использованный как `key` в `LazyColumn` вместо `cardId`) — это привело бы к неверной анимации перестановки; `key` всегда `cardId`, `CardIndex` — только отображаемое значение позиции.
- Уменьшение `size.moveButton` или `size.orderableCard.indexZoneWidth` при длинном названии или на 320 dp.
- Предложение `customAction`, не меняющего позицию карточки (например, «Переместить выше» или «Переместить в начало» у карточки, уже стоящей на первой позиции).

### MoveButton

**Назначение.** Альтернатива перетаскиванию — обязательный, не «доступностный» способ перестановки (`UX_FLOW.md`, раздел 10: кнопки полезны и зрячим пользователям).

**Анатомия.** Квадратная область 48 × 48 dp, `shape.small` (8 dp) обводка/заливка, шеврон-иконка (`icon.size.default`, вверх или вниз) по центру.

**Размеры.** `size.moveButton` = 48 × 48 dp — не имеет уменьшенного варианта.

**Токены.** `ColorScheme.primaryContainer` (заливка enabled), `ColorScheme.onPrimaryContainer` (иконка enabled), `ColorScheme.outline` (обводка disabled, без заливки), `opacity.disabledContent` (иконка disabled).

**Состояния.**

| Состояние | Заливка | Обводка | Иконка |
| --- | --- | --- | --- |
| `enabled` | `primaryContainer` | `primary` при `opacity.moveButtonEnabledBorder` (50% — визуальный акцент интерактивности) | `onPrimaryContainer`, 100% |
| `pressed` | `primaryContainer` + `opacity.pressedStateLayer` | Как в `enabled` | Как в `enabled` |
| `disabled` (первая карточка → кнопка «вверх»; последняя карточка → кнопка «вниз») | Нет заливки (прозрачный фон) | `outline` при `opacity.disabledContent` (38%) | `onSurface` при `opacity.disabledContent` (38%) |

Различие `enabled`/`disabled` — это одновременно смена цвета **и** смена формы (заливка+акцентная обводка против полностью прозрачного фона с блёклой обводкой) — соответствует правилу «disabled различим не только цветом».

**Интеракции.** Однократное нажатие двигает карточку на одну позицию в соответствующую сторону; layout-анимация перестановки — `motion.duration.long` (300 мс) / `motion.easing.standard`. `MoveButton`, ставшая `disabled` в результате хода (карточка достигла края), визуально переходит в это состояние с `motion.duration.short` (100 мс), запущенным синхронно с началом перестановки — без дополнительной задержки перед началом и без второй, отдельной анимации после.

**Длинный текст.** Не применимо — компонент не содержит текста.

**200%.** Размер не меняется (48 × 48 dp — минимум touch target, не привязан к `sp`).

**320 dp.** Без изменений — см. запрет «стрелки никогда не уменьшаются ради текста».

**Темы.** `primaryContainer`/`onPrimaryContainer` пары — те же коэффициенты, что у `CategoryLabel` (7.89:1 / 9.41:1).

**Accessibility.** Роль `Button` с `contentDescription` = «Переместить вверх»/«Переместить вниз»; на первой/последней позиции — та же роль, но состояние `disabled` объявляется TalkBack автоматически через семантику Compose (`Modifier.semantics { disabled() }` наравне с визуальным состоянием).

**TalkBack-текст.** «Переместить вверх, кнопка» / «Переместить вниз, кнопка» / то же + «недоступно» для disabled.

**Ошибки, которые нельзя допускать.** Скрытие кнопки вместо перевода в disabled (список не должен «прыгать» по ширине при исчезновении кнопки — `UX_FLOW.md`, раздел 10, требует именно `disabled`, не `visible = false`).

### DragHandle

Описан внутри `OrderableCard` (индексная зона) — здесь фиксируются размеры и accessibility отдельно, так как это самостоятельный переиспользуемый визуальный компонент.

**Назначение.** Визуальный и физический якорь для перетаскивания.

**Анатомия.** Сетка точек 2 × 3 (6 точек), заливка `onSurfaceVariant`.

**Размеры.** Визуальная сетка — `icon.size.dragHandleGlyph` (16 × 24 dp); зона захвата — `size.dragHandle.touchTarget` = 48 × 48 dp, центрирована на визуальной сетке.

**Токены.** `ColorScheme.onSurfaceVariant`, `size.dragHandle.touchTarget`, `icon.size.dragHandleGlyph`.

**Состояния.** `default`, `dragging` (сама точечная сетка не меняет цвет — изменение состояния показывает вся карточка через `elevation.dragged`/`opacity.dragStateLayer`, не точки).

**Accessibility.** Ручка не является отдельной точкой фокуса TalkBack — перестановка для TalkBack выполняется исключительно через `customActions` карточки (см. `OrderableCard`), а не через попытку симулировать перетаскивание жестом.

**Ошибки, которые нельзя допускать.** Уменьшение зоны захвата ради визуального сжатия индексной зоны.

### DragEducationHint

**Назначение.** Одноразовая контекстная подсказка о перетаскивании на первой головоломке дня (`UX_FLOW.md`, раздел 2, «Первая головоломка»). Не отдельный экран и не онбординг — плашка поверх/рядом с первой карточкой.

**Условие показа.** Только при `hasSeenDragHint == false` (флаг из `UserPreferences`, `UX_FLOW.md` раздел 2). Один раз за всё время жизни установки, не за сессию.

**Анатомия.** Компактная тональная плашка — **сплошная** заливка `surfaceContainer` (не полупрозрачная: контраст текста плашки не должен зависеть от того, что находится под ней), форма `shape.extraSmall`, внутренний padding по вертикали `spacing.200` (8 dp) и по горизонтали `spacing.300` (12 dp) из существующей spacing-шкалы. Размещается **непосредственно над первой `OrderableCard`, в потоке контента** (занимает собственное место по высоте между подписью направления сортировки и списком карточек, не оверлей поверх них) — раздвигает соседние элементы, а не перекрывает их. Она не перекрывает саму карточку, её `DragHandle`, `MoveButton` или текст задания выше по экрану: плашка занимает отдельную полосу, а не накладывается на что-либо. Текст: **«Перетащите за ручку или используйте стрелки»** (`bodyMedium`, `onSurfaceVariant`).

**Токены.** `bodyMedium`, `ColorScheme.onSurfaceVariant` (текст), `ColorScheme.surfaceContainer` (сплошной фон плашки), `shape.extraSmall` (форма), `spacing.200`/`spacing.300` (внутренний padding), `dragHint.wobbleDuration`, `dragHint.wobbleAmplitude`, `dragHint.autoHideDelay`, `dragHint.submitLockDuration` (`DESIGN_TOKENS.md`, раздел 6.8). Никаких числовых литералов в реализации компонента — все размеры, отступы, длительности и амплитуда только через перечисленные токены.

**Состояния.** `visible` (показана, покачивание первой карточки один раз за `dragHint.wobbleDuration`), `dismissed` (скрыта — по первому взаимодействию с любой карточкой набора или по истечении `dragHint.autoHideDelay`, что наступит раньше).

**Интеракции.** Не требует долгого нажатия — реагирует на любое обычное взаимодействие (нажатие `MoveButton`, начало перетаскивания за `DragHandle`) как на сигнал скрыть подсказку. `PrimaryButton` «Проверить» — `disabled` первые `dragHint.submitLockDuration` (600 мс) после появления подсказки (см. `PrimaryButton`, раздел «Состояния»).

**После показа.** Устанавливается `hasSeenDragHint = true` — независимо от того, была ли подсказка скрыта взаимодействием или таймером.

**Reduced motion.** Покачивание карточки отсутствует (амплитуда/длительность не «ускоряются», а обнуляются — раздел 6.8 `DESIGN_TOKENS.md`), текст плашки и оба таймера (`dragHint.autoHideDelay`, `dragHint.submitLockDuration`) сохраняются полностью.

**200%.** Текст плашки не обрезается: плашка растёт по высоте вместе с текстом; если суммарная высота контента экрана при этом перестаёт помещаться, экран переходит в предусмотренный для `Puzzle` scroll-режим (раздел 6.10 `DESIGN_TOKENS.md`) — подсказка не получает отдельного, специфичного только для неё правила прокрутки.

**Accessibility.** TalkBack озвучивает **«Для изменения порядка используйте действия карточки или кнопки перемещения»** — не дословный визуальный текст плашки: формулировка ориентирована на то, что у TalkBack-пользователя нет визуальной ручки для перетаскивания, зато есть `customActions` карточки и `MoveButton`. Декоративное покачивание карточки TalkBack не озвучивается вовсе (чисто визуальный эффект, не несёт дополнительной информации сверх самого текста).

**Ошибки, которые нельзя допускать.** Показ подсказки повторно в той же или следующей сессии после того, как `hasSeenDragHint` уже `true`; перекрытие плашкой `MoveButton` или `DragHandle` первой карточки; требование долгого нажатия для скрытия/подтверждения подсказки (прямо запрещено `PRODUCT.md`, риск R-5: «длинное нажатие не требуется»); озвучивание визуального текста плашки для TalkBack вместо отдельной accessibility-формулировки; числовой литерал длительности/амплитуды вместо ссылки на `dragHint.*`.

### ThreeStepProgress

**Назначение.** Индикатор «задание N из 3» — упомянут в `ARCHITECTURE.md`/`UX_FLOW.md` как «прогресс-индикатор из трёх точек». Использование зафиксировано, без вариантов:

- **виден на `Home.InProgress`** — рядом с текстом «Задание N из 3» в `DailyIssuePanel`;
- **используется в `Archive row`** — для завершённых дней все три точки в состоянии «пройдено»; для незавершённых — часть точек «пройдено», остальные «будущие» (см. `Archive row`);
- **не показывается на `Puzzle`** — там прогресс называется текстом в `AppTopBar` («Задание 1 из 3»), отдельного индикатора из точек на этом экране нет;
- **не показывается на `PuzzleResult`** — этот экран не про прогресс по трём заданиям, а про результат одного.

Компонент не «может дублироваться» где-то ещё — список выше исчерпывающий.

**Анатомия.** Три точки в ряд: пройденные — заливка `primary`; текущая — обводка `primary`, заливка `primaryContainer`; будущие — заливка `outlineVariant`.

**Размеры.** Точка — `size.progressDot.diameter` (8 dp), зазор `spacing.100` (4 dp) между точками. Компонент не интерактивен, поэтому не подчиняется правилу 48 dp touch target.

**Токены.** `ColorScheme.primary`, `ColorScheme.primaryContainer`, `ColorScheme.outlineVariant`, `size.progressDot.diameter`.

**Состояния.** Модель — два независимых поля, не одно: `mode: ActiveDay | ClosedDay` и `completedCount: Int`. Прежняя модель с одним `completedCount` 0–3 смешивала два разных места использования в одной таблице, хотя один и тот же `completedCount` рендерится по-разному в каждом из них — ниже исправленная, окончательная модель.

**`mode = ActiveDay`** — единственное место использования: `Home.InProgress`. `completedCount` — 0..2 (иначе день уже `Completed`, и `ThreeStepProgress` там не участвует — см. `DailyIssuePanel`). Первые `completedCount` точек — `primary` (пройдено); следующая точка — `current` (обводка `primary`, заливка `primaryContainer`); остальные — `outlineVariant` (будущие). Состояние `current` существует только в этом режиме.

| `completedCount` (`ActiveDay`) | Точка 1 | Точка 2 | Точка 3 |
| --- | --- | --- | --- |
| 0 | `current` | `outlineVariant` | `outlineVariant` |
| 1 | `primary` | `current` | `outlineVariant` |
| 2 | `primary` | `primary` | `current` |

**`mode = ClosedDay`** — единственное место использования: `Archive row`. `completedCount` — 0..3. Первые `completedCount` точек — `primary` (пройдено); остальные — `outlineVariant` (будущие). Состояние `current` **не существует** в этом режиме ни при каком значении `completedCount` — день закрыт, «текущего» задания в нём больше нет. `completedCount = 3` — завершённый день, все три точки `primary`; `completedCount` 0..2 — незавершённый день в архиве (`Archive row.incomplete`).

| `completedCount` (`ClosedDay`) | Точка 1 | Точка 2 | Точка 3 |
| --- | --- | --- | --- |
| 0 | `outlineVariant` | `outlineVariant` | `outlineVariant` |
| 1 | `primary` | `outlineVariant` | `outlineVariant` |
| 2 | `primary` | `primary` | `outlineVariant` |
| 3 | `primary` | `primary` | `primary` |

Итого семь валидных комбинаций (`ActiveDay` × 0–2, `ClosedDay` × 0–3), не четыре — например, `completedCount = 2` в `ActiveDay` показывает `current` на третьей точке, а тот же `completedCount = 2` в `ClosedDay` показывает на третьей точке `outlineVariant`: значение поля одно, режим разный, рендер разный.

**Accessibility.** Не самостоятельная точка фокуса ни в одном месте использования — состояние всегда дублируется текстом рядом (на `Home.InProgress` — «Задание N из 3», `bodyLarge`, внутри общего `contentDescription` `DailyIssuePanel`; в `Archive row` — статус «завершён»/«не завершён» и счёт того дня), и именно текст озвучивается TalkBack. Точки помечены `Modifier.clearAndSetSemantics {}` (декоративны относительно текста) в обоих местах использования.

**Ошибки, которые нельзя допускать.** Передача номера задания только этим индикатором без текстового дублирования — прямое нарушение правила «цвет/форма не единственный носитель состояния»; рендер `completedCount` без учёта `mode` (например, показ `current` в `ClosedDay` или ограничение `ClosedDay` диапазоном 0–2) — это два разных поля, оба обязательны для однозначного рендера.

### SourceRow

**Назначение.** Одна строка источника внутри `SourcesBlock`. Ровно **три** состояния — не два: наличия поля `url` недостаточно, чтобы решить, кликабельна ли строка, потому что обработчик `Intent.ACTION_VIEW` на устройстве может отсутствовать даже при наличии `url`.

**Анатомия, общая для всех трёх состояний.** Название источника (`bodySmall`, `onSurface`) + вид источника (`kind`, `bodySmall`, `onSurfaceVariant`) + дата обращения `accessedAt` (`bodySmall`, `onSurfaceVariant`) — показывается **всегда**, у любого источника, в любом из трёх состояний, без исключений.

**Состояния.**

| Состояние | Условие | Поведение | Accessibility |
| --- | --- | --- | --- |
| `link` | Есть `url` **и** на устройстве найден обработчик `Intent.ACTION_VIEW` | Строка кликабельна целиком; нажатие открывает браузер с этим `url`; иконка внешнего перехода (`icon.size.small`) справа. `reference`, если он также присутствует в данных источника, показывается тоже (`CONTENT_MODEL.md` допускает оба поля одновременно — `reference` не скрывается из-за наличия `url`) | `contentDescription` = «{Название источника}. Открыть источник в браузере»; роль `Button`/`Link` |
| `urlPlainText` | Есть `url`, но обработчика `Intent.ACTION_VIEW` на устройстве нет (`resolveActivity() == null`) | Строка **некликабельна**, без иконки и без интерактивной роли; сам `url` показывается как обычный читаемый текст (`bodySmall`, `onSurfaceVariant`) — не прячется и не заменяется плейсхолдером; `reference`, если он также есть, показывается рядом | Обычный текстовый узел, без интерактивной роли |
| `referenceOnly` | `url` отсутствует | `reference` **обязателен** по модели контента (`CONTENT_MODEL.md`: у источника обязательно есть `url` или `reference`) и показывается всегда в этом состоянии; строка некликабельна, без внешней иконки | Обычный текстовый узел, без интерактивной роли |

Отсутствие обработчика `ACTION_VIEW` **не** прячет строку и не показывает ошибку — источник деградирует до `urlPlainText` и остаётся полностью читаемым как текст (тот же принцип деградации, что у `ReportInaccuracyAction`: функциональность пропадает тихо, содержание — никогда).

**Русская подпись `kind` — точное отображение.** `Source.kind` — enum со значениями `official`/`encyclopedia`/`academic`/`other`. Raw-значение enum **никогда** не показывается пользователю ни в каком виде (ни как fallback, ни как отладочный текст); в UI всегда идёт готовая русская подпись, взятая как строковый ресурс:

| `kind` (raw, только код) | Подпись в `SourceRow` (строковый ресурс) |
| --- | --- |
| `official` | «Официальный источник» |
| `encyclopedia` | «Энциклопедия» |
| `academic` | «Научный источник» |
| `other` | «Дополнительный источник» |

Все четыре подписи — строковые ресурсы (`res/values/strings.xml`), не литералы в коде компонента. Значение `other` → «Дополнительный источник» — это **только** пользовательская подпись вида источника; она не делает источник авторитетным и не участвует ни в каком расчёте авторитетности — правила авторитетности источников заданы отдельно в `CONTENT_MODEL.md` и этой подписью не меняются и не подменяются. Значение enum, не входящее в перечисленные четыре (данные с ошибкой), — это ошибка данных, а не повод показать raw-строку или произвольный fallback-текст (см. «Ошибки, которые нельзя допускать» ниже).

**Размеры.** Высота строки — по содержимому, минимум `size.touchTarget.min` (48 dp) для состояния `link` (это интерактивный элемент); для `urlPlainText` и `referenceOnly` минимальная высота не требуется — это обычные текстовые блоки.

**Токены.** `bodySmall`, `ColorScheme.onSurfaceVariant` (вид источника, `reference`, `url`-как-текст, дата), `ColorScheme.onSurface` (название источника, во всех трёх состояниях), `icon.size.small` (иконка перехода, только `link`).

**Сеть.** `Intent.ACTION_VIEW` передаёт переход внешнему браузеру — сам браузер выполняет сетевой запрос, не приложение. Собственного сетевого запроса приложение не выполняет, и разрешение `android.permission.INTERNET` для этого поведения не требуется (тот же принцип, что уже действует для `mailto`-действия «Сообщить о неточности», `UX_FLOW.md`, раздел 5) — это согласуется с критерием `IMPLEMENTATION_PLAN.md`, итерация 7: «нет ни одного сетевого разрешения и ни одного сетевого вызова».

**Интеракции.** `link` — однократное нажатие → системный выбор браузера (если установлено несколько) → переход. `urlPlainText`/`referenceOnly` — нет интеракций.

**Темы.** `onSurface`/`onSurfaceVariant` на `surface` — 13.75:1 / 6.28:1 (light), 14.08:1 / 8.22:1 (dark).

**Accessibility.** См. таблицу состояний. `link`-строка — полноценная сенсорная цель (не только текст иконки), `contentDescription` обязательно включает название источника, а не только шаблонную фразу («Открыть источник в браузере» без названия — недостаточно, TalkBack-пользователь не поймёт, какой именно источник открывается). `urlPlainText`/`referenceOnly`-строки не должны быть достижимы фокусом как интерактивный элемент (это обычный текст, TalkBack не объявляет их как кнопку/ссылку).

**Ошибки, которые нельзя допускать.** Кликабельность у `urlPlainText`- или `referenceOnly`-строки; отсутствие иконки перехода у `link`-строки; `contentDescription` без названия источника; скрытие `reference` при одновременном наличии `url` (в состояниях `link` и `urlPlainText`); скрытие `accessedAt` в любом из трёх состояний; трактовка `urlPlainText` как `referenceOnly` (это разные условия: `urlPlainText` показывает `url`-текст, `referenceOnly` показывает `reference` — путать их значит терять информацию об источнике, у которого есть `url`, но нет обработчика); отсутствие `reference` в анатомии `referenceOnly`, будто оно опционально; показ raw-значения `kind` (`official`/`encyclopedia`/`academic`/`other`) вместо русской подписи из таблицы выше; показ неизвестного значения `kind` как произвольного fallback-текста вместо обработки как ошибки данных; трактовка подписи «Дополнительный источник» как признака авторитетности источника.

### ReportInaccuracyAction

| Состояние | Условие | Поведение |

**Ошибки, которые нельзя допускать.** Показ строки в состоянии `disabled` вместо полного отсутствия при `resolveActivity() == null`; сбор и передача любых данных о пользователе, результатах или прогрессе в тело письма сверх `puzzleId`/версии приложения/версии контента.

### DayResultRow

**Назначение.** Одна из трёх строк на `DayRecap` — категория и результат одного задания.

**Анатомия.** `CategoryLabel` (переиспользуется) + результат «N из 6» (`bodyLarge`).

**Адаптивная схема — решение принимается для всего списка сразу, не для каждой строки.**

На `DayRecap` этих строк всегда ровно три, и они читаются как один список. Поэтому раскладка выбирается один раз, по всем трём, и применяется ко всем трём:

- **`inline`** — `CategoryLabel` слева, результат «N из 6» прижат к правому краю контентной колонки, обе части на одной строке;
- **`stacked`** — `CategoryLabel` сверху, результат под ней, обе части выровнены по левому краю контентной колонки.

**Правило выбора.** Если хотя бы одна из трёх строк не помещается в `inline` при текущей ширине и текущем масштабе шрифта — проверяемое условие `ширина CategoryLabel + spacing.400 + ширина результата > ширина контентной колонки` — весь список переходит в `stacked` целиком. Смешанной раскладки, где часть строк в одну строку, а часть в две, **не существует ни при какой ширине и ни при каком масштабе шрифта**: это дефект, а не адаптация. Артборд 12 предыдущей ревизии показывал именно его — «География» и «История» вертикально, «Наука» горизонтально — и это исправлено.

**Единообразие внутри `stacked`** (все три строки, без исключений):

| Величина | Значение |
| --- | --- |
| Верхний внутренний отступ строки | `spacing.200` (8 dp) |
| Зазор `CategoryLabel` → результат | `spacing.300` (12 dp) |
| Нижний внутренний отступ строки | `spacing.200` (8 dp) |
| Выравнивание обеих частей | По левому краю контентной колонки |
| Высотная логика | Высота = отступы + фактическая высота `CategoryLabel` + фактическая высота строки результата; фиксированной высоты нет ни у одной из трёх |
| Разделитель | Hairline `outlineVariant` толщиной `size.divider.thickness` под каждой строкой, включая последнюю (она отделяет список от `StreakRow`) |

Ни `CategoryLabel`, ни результат при переходе в `stacked` не уменьшаются: меняется расположение, а не размеры — тот же принцип «растёт по высоте, не сжимается по ширине», что уже действует для `OrderableCard`, `HomeHeader` и `AppTopBar`.

**Токены.** `CategoryLabel`, `bodyLarge`, `outlineVariant` (hairline между строками), `spacing.200`/`spacing.300`/`spacing.400`.

**Состояния.** `completed` (обычный случай), `skipped` (задание было пропущено при ошибке контента — результат «0 из 6», подпись не отличается по цвету, только по числу — `UX_FLOW.md`, раздел 11). Раскладка (`inline`/`stacked`) — не состояние строки, а свойство всего списка: два разных состояния строк могут соседствовать, две разные раскладки — нет.

**200%.** На 320 dp при 200% ни одна из трёх строк не помещается в `inline`, поэтому список целиком переходит в `stacked` — см. артборд 12.

**Ошибки, которые нельзя допускать.** Раскрытие формулировки задания на этом экране — `DayRecap` показывает только категорию и число, не текст задания (`UX_FLOW.md`, раздел 6: «без формулировок»); смешанная раскладка внутри списка из трёх строк; разные внутренние отступы или разное выравнивание у строк одного списка; уменьшение `CategoryLabel` или кегля результата вместо перехода в `stacked`.

### ShareCard

**Назначение.** Текстовый payload для «Поделиться». **Это не визуальный Compose-компонент** — это результат работы `ShareCardBuilder` (обычная строка), переданный в системный `Intent.ACTION_SEND`. В MVP встроенного превью этой карточки внутри приложения нет: кнопка «Поделиться» сразу открывает системный share sheet, без промежуточного экрана.

**Формат (окончательный, строго по `UX_FLOW.md`, раздел 6). Ровно семь строк, без вариантов.**

```
По порядку! · День 12
15/18
🟩🟩🟩🟩🟩🟩
🟩🟩🟩🟩⬜⬜
🟩🟩🟩🟩🟩⬜
Серия: 6 дней
{RU_STORE_URL}
```

Построчно: 1 — название продукта и «День N» (номер набора пользователя, не календарная дата); 2 — счёт дня «N/18»; 3–5 — три строки по шесть символов, по одной на головоломку, по одному символу на пару; 6 — серия; 7 — ссылка на приложение, **последняя обязательная строка**. Без названий заданий, категорий и правильных порядков ни в одной строке.

`{RU_STORE_URL}` — не литерал в коде `ShareCardBuilder`. Значение берётся из строкового ресурса, заполняемого релизной конфигурацией (`UX_FLOW.md`, раздел 6: «ссылка на приложение — отдельной строкой (текст в ресурсах, ссылка RuStore подставляется на этапе релиза)») — до релиза строка ресурса может быть плейсхолдером, но `ShareCardBuilder` всегда читает её из ресурса, никогда не формирует URL сам. Формат остаётся без вариантов после этого исправления — семь строк, ни одна не опциональна.

**Символы 🟩/⬜ — единственное исключение из запрета на эмодзи** (`DESIGN_PRINCIPLES.md`, раздел 8): это содержимое текстовой строки для внешнего получателя, а не иконка интерфейса приложения — ни на одном экране Compose эти символы не отображаются как UI.

**Токены.** Нет — `ShareCardBuilder` строит обычную Kotlin-строку, не Compose UI; типографических/цветовых токенов не применяет и не нуждается в них.

**Интеракции.** Нажатие «Поделиться» на `DayRecap` → `Intent.ACTION_SEND` с этой строкой как `EXTRA_TEXT` → системный выбор приложения для отправки. Действие однократное и непосредственное, без предварительного показа карточки внутри приложения.

**Ошибки, которые нельзя допускать.** Добавление названий заданий, категорий или правильных порядков в текст — прямой запрет `UX_FLOW.md`, раздел 6; создание визуального Compose-превью карточки перед отправкой (в MVP не предусмотрено — если появится, потребует отдельного решения и обновления этого документа, а не тихого добавления в код); использование эмодзи, отличных от 🟩/⬜, в этой или любой другой строке продукта.

### Settings row

**Анатомия.** Заголовок настройки (`bodyLarge`) слева, элемент управления справа (переключатель, выбор темы или шеврон для перехода на подэкран).

**Токены.** `bodyLarge`, `ColorScheme.primary` (включённый `Switch`, стандартный M3-компонент, не кастомный), `outlineVariant` (разделитель строк), `size.touchTarget.min` (вся строка — минимум 48 dp высотой, даже если текст компактнее).

**Состояния.** `on`/`off` для обычных переключателей (звук, вибрация, тема). **Переключатель «Напоминание» не имеет постоянного `disabled`-состояния из-за отсутствия разрешения** — он всегда нажимаем. Точный поток:

| Шаг | Поведение |
| --- | --- |
| Переключатель выключен, пользователь включает | Если системное разрешение на уведомления ещё не выдано — запрашивается системный диалог разрешения (`POST_NOTIFICATIONS`) |
| Пользователь разрешает | Переключатель остаётся в `on`, показывается выбор времени |
| Пользователь отказывает | Переключатель немедленно возвращается в `off`; под строкой появляется текст `bodySmall` «Разрешите уведомления в настройках системы» (не всплывающее окно, встроенная строка-подсказка) |
| Разрешение было отозвано вне приложения (настройки ОС) с момента последнего открытия | При следующем открытии `Settings` переключатель показывается в `off` (сверка с системным состоянием разрешения при построении экрана, `UX_FLOW.md`, раздел 11: «Переключатель показывает выключенное состояние при следующем открытии настроек») |

Переключатель нажимаем в любой момент независимо от текущего статуса разрешения — «выключен» и «недоступен» не путаются между собой, второго нет вовсе.

**Ошибки, которые нельзя допускать.** Обёртывание каждой строки настроек в отдельную `Card`-поверхность (нарушение anti-slop «карточка вокруг каждого текста», `DESIGN_PRINCIPLES.md` раздел 11) — строки разделены исключительно hairline.

### Loading skeleton

**Анатомия — правило одно: каждый skeleton повторяет силуэт целевого компонента, не общую прямоугольную заглушку.** Заливка `surfaceContainer` во всех случаях, без анимации пульсации (пульсирующий skeleton — не запрещён явно продуктовыми документами, но не описан ни разу в `UX_FLOW.md`; в отсутствие явного разрешения на анимацию, `Loading` показывается статичным плейсхолдером — соответствует принципу «если правила нет, не изобретать за экраном»). Форма зависит от того, что именно заменяет плейсхолдер:

- skeleton `OrderableCard` — форма `OrderableCardCutCorner` (не `shape.medium`!) и та же `size.orderableCard.minHeight` — целевой компонент имеет срезанный угол, и его skeleton обязан иметь его тоже (см. «Ошибки, которые нельзя допускать» ниже);
- skeleton `DailyIssuePanel` на `Home.Loading` — тот же силуэт со `spine` слева, без текста внутри;
- `Statistics block` — не отдельная карточка/контейнер (см. state sheet `Statistics block` выше: заголовок и построчные пары метка/значение без собственной поверхности), поэтому его skeleton не получает формы `shape.medium` или любой другой формы контейнера — нет цели-контейнера, форму которой нужно было бы повторить. Плейсхолдер — отдельные текстовые полосы (заливка `surfaceContainer`, без формы-контейнера вокруг), по одной на каждую пару метка/значение, повторяющие построчную структуру блока, без изобретения для них общей обёртки;
- skeleton любого остального компонента без собственной нестандартной формы контейнера (кроме двух случаев выше) — `shape.medium`, тот же принцип «форма как у цели».

**Токены.** `shape.medium`, `ColorScheme.surfaceContainer`.

**Ошибки, которые нельзя допускать.** Skeleton-версия `OrderableCard` **обязана** повторять форму `OrderableCardCutCorner`, включая срезанный верхний правый угол — не только габариты. Прямоугольный skeleton без среза под `OrderableCard` — дефект: он предвосхищает не ту форму, которая появится после загрузки, и визуально «дёргается» в момент подмены.

### Error

Один универсальный вариант с обязательной кнопкой «Повторить» не покрывает продукт — на разных экранах ошибка ведёт к разным действиям. Зафиксировано ровно три варианта; смешивать действие одного варианта с текстом другого запрещено.

**Общее для всех трёх.** Текст ошибки — нейтральный `bodyLarge`, `onSurface`, без `error`-цвета. `ColorScheme.error`/`errorContainer` не используются ни в одном из трёх вариантов — роль зарезервирована на будущее (например, валидация форм) и не задействуется в MVP, чтобы не создавать визуальный тон «тревоги», противоречащий спокойному продукту.

#### `retryable` — Home, Archive

**Анатомия.** Точный текст состояния экрана (`Home.Error`: «Не удалось загрузить задания»; `Archive.Error`: «Не удалось прочитать историю» — `UX_FLOW.md`, разделы 3 и 7) + `PrimaryButton` «Повторить».

**Токены.** `bodyLarge`, `PrimaryButton`.

#### `skippablePuzzle` — Puzzle.Error

**Анатомия.** Текст «Задание недоступно» + `SecondaryButton` «Пропустить» (**не** `PrimaryButton` и **не** «Повторить» — на этом экране нет действия «повторить попытку загрузки», есть только переход дальше). Результат пропущенного задания фиксируется как 0 баллов, день можно завершить на оставшихся заданиях (`UX_FLOW.md`, раздел 4; раздел 11: «не роняем день»).

**Токены.** `bodyLarge`, `SecondaryButton`.

#### `recapMissing` — DayRecap.Error

**Анатомия.** Текст «Данные за этот день не сохранились» (`UX_FLOW.md`, раздел 6). **Без кнопки «Повторить»** — повторная попытка ничего не изменит, данных за прошедший день больше нет ни при каком количестве попыток. Возврат — через `AppTopBar` (кнопка «назад»), не через выдуманную кнопку действия на самом экране.

**Токены.** `bodyLarge`, `AppTopBar`.

**Ошибки, которые нельзя допускать.** Кнопка «Повторить» на `recapMissing` (там нечего повторять); кнопка «Пропустить» или «Повторить» вместо `AppTopBar`-навигации на `recapMissing`; `PrimaryButton` вместо `SecondaryButton` на `skippablePuzzle` (это не основное, а второстепенное действие — основное действие этого экрана уже недоступно); использование текста одного варианта на экране другого (например, «Не удалось загрузить задания» на `Puzzle.Error`); `ColorScheme.error`/`errorContainer` для текста или фона в любом из трёх вариантов.

### NotificationOptInDialog

**Назначение.** Одноразовое предложение включить напоминание, показывается на `DayRecap` после первого полностью завершённого дня (`UX_FLOW.md`, «Права и разрешения»). Отдельного полноэкранного артборда не требует — это state sheet, не экран.

**Функциональное исключение из правил форм и теней.** Это единственный диалог в MVP и **второе** (наряду с `OrderableCard.dragging`) состояние продукта с настоящей тенью — и то, и другое исключение зафиксировано явно, а не как побочный эффект. Утверждения «диалогов в MVP нет» и «`elevation.dialog` — резерв» из более ранней редакции документов сняты: диалог есть, ровно один, и токены `shape.large`, `surfaceContainerHigh`, `elevation.dialog`, `opacity.scrim` для него активно используются, не зарезервированы.

**Форма и тень диалога не распространяются на другие компоненты.** `shape.large`/`elevation.dialog` не применяются ни к `OrderableCard`, ни к `DailyIssuePanel`, ни к любому другому обычному контейнеру — это исключение только для модального слоя, а не прецедент для «карточек поважнее».

**Условие показа.** `notificationPromptShown == false` **и** сегодняшний день только что полностью завершён (переход на `DayRecap` после третьего задания в первый раз, когда это условие выполняется).

**Анатомия — один вариант, без альтернатив.** Текст вопроса **«Напоминать о новом задании?»** — единственный заголовок диалога, роль `titleMedium` (не отдельный заголовок плюс дублирующий `bodyLarge` — это один текстовый узел, а не два) → две кнопки действий: **«Да, в 9:00»** (`PrimaryButton`) и **«Не нужно»** (`SecondaryButton` — определённо, не «текстовое действие»).

**Токены.** `shape.large`, `ColorScheme.surfaceContainerHigh` (заливка), `elevation.dialog`, `ColorScheme.scrim`/`opacity.scrim` (затемнение фона), `titleMedium` (текст вопроса — единственный текстовый узел диалога), `PrimaryButton`, `SecondaryButton`.

**Состояния.** `visible` (показан один раз), `dismissed` (закрыт любым способом).

**Интеракции и переходы.**

`dismissOnClickOutside = false` — касание вне диалога **не закрывает его и не эквивалентно никакому действию**: диалог остаётся открытым, пока пользователь не выберет один из двух явных вариантов или не нажмёт системную кнопку «назад». Это единственный способ закрыть диалог без явного выбора.

| Действие пользователя | Результат |
| --- | --- |
| «Да, в 9:00» | Запускает системный запрос `POST_NOTIFICATIONS` на версиях Android, где он требуется. При разрешении — включается напоминание на 9:00. При отказе в системном диалоге — напоминание остаётся выключенным (это тот же путь, что описан в `Settings row`: отказ не заставляет пользователя лезть в настройки повторно, просто ничего не включается) |
| «Не нужно» | Закрывает диалог **без** системного запроса разрешения — ничего не включается, разрешение не запрашивается |
| Системная кнопка «назад» | Эквивалентна «Не нужно»: диалог закрывается без системного запроса |
| Касание вне диалога | Ничего не происходит (`dismissOnClickOutside = false`) — диалог остаётся открытым |

**После любого способа завершения диалога — всегда.** Устанавливается `notificationPromptShown = true` при «Да, в 9:00», при «Не нужно» и при системной кнопке «назад» — ровно трёх действиях, которыми диалог вообще можно завершить (касание вне диалога не завершает его, см. `dismissOnClickOutside = false` выше, и потому не устанавливает флаг). Диалог **не показывается повторно автоматически** ни при каких условиях. Дальнейшее включение напоминания доступно только через `Settings row` (тот же переключатель «Напоминание», та же логика системного разрешения).

**200%.** Содержимое диалога прокручивается при необходимости (текст вопроса не обрезается); действия («Да, в 9:00» / «Не нужно») складываются вертикально вместо горизонтальной пары при недостатке ширины — обе кнопки сохраняют `size.button.height` и `size.touchTarget.min`.

**Темы.** `onSurface`/`surfaceContainerHigh` — рассчитано независимо по WCAG для этой конкретной пары (не взято по аналогии с `surfaceContainerLow`): **12.56:1** в светлой теме (`#23241F` на `#EFE6CE`), **10.93:1** в тёмной теме (`#EDE7D8` на `#332E24`). Оба значения — раздел 6.2 `DESIGN_TOKENS.md`.

**Accessibility.** Первый TalkBack-фокус при открытии диалога — заголовок/текст вопроса («Напоминать о новом задании?»), затем оба действия в порядке «Да, в 9:00» → «Не нужно». Диалог — модальная роль (фокус не уходит на контент под `scrim`, пока диалог открыт).

**Ошибки, которые нельзя допускать.** Повторный автоматический показ после того, как `notificationPromptShown` уже `true`; запрос `POST_NOTIFICATIONS` при нажатии «Не нужно» или при закрытии диалога без явного согласия; применение `shape.large`/`elevation.dialog` к любому не-диалоговому компоненту; показ диалога до полного завершения первого дня или на любом экране, кроме `DayRecap`.
