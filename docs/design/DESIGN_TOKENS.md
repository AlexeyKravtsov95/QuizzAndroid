# DESIGN_TOKENS.md — «По порядку!»

Design Gate, часть B1. Статус: утверждено, 2026-08-30. Полный набор именованных значений для механического переноса в Jetpack Compose Material 3. Направление — концепция D (`design/concepts/concept-d.svg`, `design/concepts/HYBRID.md`).

**Правило на весь код продукта:** если значение нужно для реализации и его нет в этом документе — работа останавливается, значение добавляется сюда (с обоснованием и, если это цвет, — с проверкой контраста), и только после этого код продолжается. Захардкоженный HEX, `dp`, `sp`, кривая или длительность вне этого документа — дефект, равнозначный функциональной ошибке (`ARCHITECTURE.md`, раздел 11).

## 6.1 Именование и уровни токенов

Три уровня, снизу вверх. Компонент **не имеет права** обращаться к примитивному токену напрямую — только к семантическому или компонентному.

| Уровень | Что это | Пример имени | Кто может использовать |
| --- | --- | --- | --- |
| **Примитивный (primitive)** | Сырое значение палитры/шкалы, без роли | `palette.pine700`, `scale.space.400`, `scale.radius.200` | Только определения семантических токенов в этом документе |
| **Семантический (semantic)** | Названная роль: что означает значение, а не как оно выглядит | `ColorScheme.primary`, `Typography.headlineSmall`, `Spacing.marginDefault`, `Shape.medium` | Компоненты и экраны |
| **Компонентный (component)** | Переопределение семантического токена для конкретного компонента, всегда ссылкой, никогда новым значением | `OrderableCardTokens.indexZoneWidth = Spacing.indexZone`, `PrimaryButtonTokens.height = Sizing.buttonHeight` | Только реализация одноимённого компонента |

Правила:

- Светлая и тёмная тема **не создают отдельных имён**. Токен `ColorScheme.primary` один; у него два разрешаемых значения (light/dark), выбираемых Compose через `isSystemInDarkTheme()` и `UserPreferences.theme`. Ни один компонент не содержит условие `if (isDark) Color(...) else Color(...)` — переключение темы происходит только через `MaterialTheme.colorScheme`.
- Запрещено использовать в компонентах raw `Color(0xFF...)`, безымянный `.dp`/`.sp`-литерал или числовую длительность анимации. Каждое такое значение обязано быть полем в `AppTheme`/`AppTokens`, определённым здесь.
- Имена ролей цвета соответствуют текущим полям `androidx.compose.material3.ColorScheme` буква в букву (`primary`, `onPrimaryContainer`, `surfaceContainerHighest` и т.д.), чтобы присвоение было механическим: `ColorScheme(primary = ColorTokens.primaryLight, ...)`.

**Примечание про `background`/`onBackground`.** В актуальном Material 3 эти роли фактически объединены с `surface`/`onSurface` (см. material-3 skill, раздел «Color Tokens»). Здесь они намеренно равны `surface`/`onSurface` буквально, а не «похожи»: `ColorScheme.background = ColorScheme.surface` в обеих темах. Отдельного алгоритма для `background` нет.

**Disabled-состояния.** Цвет disabled-элементов не обязан проходить 4.5:1 (WCAG 1.4.3 явно освобождает неактивные компоненты). В продукте это: обводка disabled-`MoveButton` и disabled-`PrimaryButton` — `outline` с `opacity.disabledContent` (раздел 6.9), текст/иконка внутри — `onSurface` при той же непрозрачности. **Само состояние обязано иметь второй, не цветовой признак** — обводка без заливки (enabled-кнопка залита `primary`/`primaryContainer`, disabled — нет заливки вообще, только `outline`-обводка сниженной непрозрачности). Признак закреплён в `COMPONENTS.md`, раздел «OrderableCard» → `MoveButton`, и раздел `PrimaryButton` (три места использования в MVP: `Puzzle.Loading`, первые `dragHint.submitLockDuration` после `DragEducationHint`, при необходимости — `Submitting`).

**Ни одно состояние продукта не передаётся только цветом** — перекрёстная проверка по компонентам в `COMPONENTS.md`, раздел «Touch targets и accessibility».

### Fixed-роли (`primaryFixed`/`secondaryFixed`/`tertiaryFixed` семейства)

**Пересчёт `on*FixedVariant` (эта ревизия).** Прежние значения (`#637A6E`/`#66726B`/`#946353`) проходили только «AA-крупный» (≥3:1) и не проходили обычный текстовый контраст 4.5:1, особенно на более тёмной `*FixedDim` — это дефект для роли, предназначенной для обычного текста. Новые значения подобраны так, чтобы (а) обе поверхности `*Fixed` и `*FixedDim` проходили ≥4.5:1, и (б) итоговый тон оставался светлее и менее ощутимо «весомым», чем основной `on*Fixed` того же семейства (сверено по относительной светимости, не на глаз: во всех трёх случаях светимость `*FixedVariant`-текста выше, чем у `on*Fixed`). Расчёт — независимый (формула WCAG, не копия ориентиров задания).

**Использование в MVP: не задействованы ни одним компонентом `COMPONENTS.md`.** Роли добавлены исключительно для полной механической реализации `ColorScheme` (без пропусков полей при создании `lightColorScheme()`/`darkColorScheme()`) — это явно обозначенный неиспользуемый резерв, а не открытый вопрос дизайна. Появление продуктовой причины для их использования (например, элемент, который обязан визуально не меняться при переключении темы) требует отдельного решения через обновление `COMPONENTS.md`, а не самостоятельного применения в коде.

| Минимальная высота `CategoryLabel` | `size.categoryLabel.minHeight` | 26 dp (`minHeight`, не фиксированная высота — при 200% контейнер растёт по содержимому текста, не остаётся 26 dp) |
| Визуальный индикатор `DragHandle` (сетка точек, внутри `size.dragHandle.touchTarget`) | `icon.size.dragHandleGlyph` | 16 × 24 dp |
| Диаметр точки `ThreeStepProgress` | `size.progressDot.diameter` | 8 dp |

**Расстояние между соседними touch target на Home.** Иконки архива и настроек — независимые области `size.headerIcon` (48 × 48 dp) каждая, без пересечения; минимальный зазор между их границами — `spacing.200` = 8 dp, что при центрах на расстоянии `48 + 8 = 56 dp` превышает сам размер цели (48 dp) — требование раздела 7 задания выполнено буквально.

**Puzzle vertical budget (390 × 844 — полный размер окна эталонного телефона, системный шрифт 100%).**

`390 × 844 dp` — это полная высота окна устройства, а не высота, уже доступная под контент. Верхний и нижний `safeDrawing` inset (статус-бар, жестовая/кнопочная навигация) — динамические значения из `WindowInsets`, не токены (раздел 6.10) — здесь их типичные величины показаны отдельно и явно вычтены, а не «зашиты» в 844 dp и не приняты за запас:

| Величина | Значение | Комментарий |
| --- | --- | --- |
| `windowHeight` | 844 dp | Полная высота окна эталонного телефона — константа для расчёта, не токен |
| `topInset` (типично) | 24 dp | Статус-бар — типичная величина для расчёта, реальное значение приходит из `WindowInsets.statusBars` в рантайме |
| `bottomInset`, жестовая навигация (типичный современный случай) | 24 dp | `WindowInsets.navigationBars` при включённой жестовой навигации |
| `bottomInset`, кнопочная навигация (худший обычный случай) | 48 dp | `WindowInsets.navigationBars` при классической 3-кнопочной навигации — доступна пользователю на любом устройстве с minSdk 26, бюджет обязан выдерживать и этот случай |
| `availableHeight = windowHeight − topInset − bottomInset`, жестовая навигация | 844 − 24 − 24 = **796 dp** | Расчётный случай A |
| `availableHeight`, кнопочная навигация | 844 − 24 − 48 = **772 dp** | Расчётный случай B — более жёсткий, именно по нему проверяется бюджет ниже |

Сумма содержимого экрана `Puzzle.Playing` внутри `availableHeight` (после исключения inset, не до):

`AppTopBar` (56 dp) + `spacing.section` (24 dp) + формулировка задания `EditorialTitle` до 3 строк (30 dp lineHeight × 3 = 90 dp) + подпись направления `bodyMedium` (20 dp lineHeight) + `spacing.300` (12 dp) + 4 × `size.orderableCard.minHeight` (4 × 112 = 448 dp) + 3 × `spacing.listGap` (3 × 12 = 36 dp) + `spacing.section` (24 dp) + `size.button.height` (56 dp) = **766 dp**.

Проверка против обоих случаев: 766 dp ≤ 772 dp (случай B, кнопочная навигация) — запас **6 dp**; 766 dp ≤ 796 dp (случай A, жестовая навигация) — запас **30 dp**. Оба запаса неотрицательны — задание помещается без обязательной прокрутки на эталонном телефоне при 100% шрифте в обоих распространённых сценариях навигации.

Ради этого расчёта скорректированы два токена относительно первой редакции документа: `size.orderableCard.minHeight` (120 → 112 dp) и `spacing.listGap` (`spacing.400` → `spacing.300`, 16 → 12 dp). **Ни один accessibility-размер при этом не пострадал**: `size.moveButton` (48 × 48 dp), `size.dragHandle.touchTarget` (48 × 48 dp), `size.orderableCard.indexZoneWidth` (56 dp), `size.cutCorner` (18 dp) и все размеры типографики остались без изменений — раскладка внутри уменьшенной `minHeight` явно показана в строке `size.orderableCard.minHeight` выше и подтверждает, что обе кнопки перемещения сохраняют полный размер.

Запас 6 dp в худшем случае — это результат расчёта по `lineHeight`, а не наблюдение на готовом макете: реальный рендер шрифта на конкретном устройстве может отличаться на несколько dp в любую сторону. Поэтому бюджет — расчётный ориентир для вёрстки, а не гарантия отсутствия прокрутки в каждой возможной комбинации устройства/шрифта/локали; на этот случай уже предусмотрен сценарий прокрутки с авто-скроллом при перетаскивании (`UX_FLOW.md`, раздел 4; раздел 6.10 ниже). Данный расчёт не является визуальным доказательством — окончательное визуальное подтверждение раскладки относится к артбордам следующего этапа (Design Gate, часть B2), не к этому документу.

## 6.6 Shapes

| Роль | Токен | Радиус | Применение |
| --- | --- | --- | --- |
| Нет скругления | `shape.none` | 0 dp | Не используется ни одним компонентом продукта (зафиксировано для полноты системы M3) |
| Очень малый | `shape.extraSmall` | 4 dp | `CategoryLabel`, `DragEducationHint` |
| Малый | `shape.small` | 8 dp | `PrimaryButton`, `SecondaryButton`, `MoveButton` |
| Средний | `shape.medium` | 12 dp | Три обычных (не срезанных) угла `OrderableCard`; форма подходящих skeleton-плейсхолдеров (`Loading skeleton`) там, где целевой компонент сам не имеет `OrderableCardCutCorner` |
| Крупный | `shape.large` | 16 dp | `NotificationOptInDialog` — единственный диалог MVP |
| Очень крупный | `shape.extraLarge` | 28 dp | Резерв: `bottom sheet`, если появится после MVP |
| Полное скругление (pill) | — | **Не определено намеренно.** В системе нет токена `shape.full`/pill — ни один компонент не имеет права на радиус, равный половине своей высоты | — |

### Custom shape: `OrderableCardCutCorner`

Единственная нестандартная форма в системе. Параметры:

- `cornerRadius` = `shape.medium` (12 dp) — применяется к трём обычным углам (низ-лево, низ-право, верх-лево);
- `cutSize` = `size.cutCorner` (18 dp) — прямой диагональный срез верхнего правого угла, заменяющий там скругление; отрезок между точкой на верхней грани (на 18 dp левее правого края) и точкой на правой грани (на 18 dp ниже верхнего края);
- `cutSize` — константа, **не масштабируется** ни шириной карточки (320–большие экраны), ни её высотой (100–200% шрифта). На карточке, выросшей по высоте из-за длинного заголовка, срез визуально кажется меньше относительно целого — это ожидаемо и допустимо (зафиксировано в `HYBRID.md`, раздел 11).

**Запрет.** `OrderableCardCutCorner` не применяется ни к одному другому компоненту — ни к `PrimaryButton`, ни к `CategoryLabel`, ни к `DailyIssuePanel`, ни к будущим диалогам. Если новому компоненту «хочется» такой же срез — это сигнал остановиться и пересмотреть `DESIGN_PRINCIPLES.md`, раздел 6, а не тихо переиспользовать форму.

## 6.7 Elevation

| Состояние | Токен | Значение | Тень | Комментарий |
| --- | --- | --- | --- | --- |
| Покой | `elevation.resting` | 0 dp | Нет | Состояние по умолчанию для всех компонентов, включая `OrderableCard` вне перетаскивания |
| Нажатие | `elevation.pressed` | 0 dp | Нет | Обратная связь — только `state layer` (раздел 6.9), не тень |
| Перетаскивание | `elevation.dragged` | 6 dp | Да, стандартная M3-тень уровня 3 | Одно из двух состояний продукта с настоящей тенью (второе — `elevation.dialog`, ниже) |
| Диалог | `elevation.dialog` | 6 dp | Да | `NotificationOptInDialog` — второе (и единственное кроме перетаскивания) состояние продукта с настоящей тенью, функциональное: тень отделяет модальный слой от контента под ним, а не декорирует |
| Оверлей (меню/подсказка) | `elevation.overlay` | 3 dp | Да, стандартная M3-тень уровня 2 | Резерв — меню в MVP нет |

Правило: `elevation` любого компонента вне списка выше равен `elevation.resting`. Функциональный подъём — это физическое перетаскивание пользователем (`OrderableCard.dragging`) и системная модальность (`NotificationOptInDialog`, единственный диалог MVP) — не более двух исключений; визуальный акцент («эта карточка/этот блок важнее») elevation-ом не выражается никогда ни для чего третьего. Форма и тень диалога не распространяются на обычные карточки — `OrderableCard`, `DailyIssuePanel` и любой другой контейнер продолжают использовать `shape.medium`/`elevation.resting`.

## 6.8 Motion

Кривые — точные значения текущей спецификации Material 3 (сверено с material-3 skill), не собственное изобретение:

| Кривая | Токен | cubic-bezier |
| --- | --- | --- |
| Standard | `motion.easing.standard` | `(0.2, 0, 0, 1)` |
| Standard decelerate | `motion.easing.standardDecelerate` | `(0, 0, 0, 1)` |
| Standard accelerate | `motion.easing.standardAccelerate` | `(0.3, 0, 1, 1)` |
| Emphasized decelerate | `motion.easing.emphasizedDecelerate` | `(0.05, 0.7, 0.1, 1)` |
| Linear | `motion.easing.linear` | `(0, 0, 1, 1)` |

Длительности:

| Токен | Значение | Применение |
| --- | --- | --- |
| `motion.duration.short` | 100 мс | `state layer` при нажатии; визуальная смена `enabled`↔`disabled` у `MoveButton` (начинается синхронно с `motion.duration.long`-перестановкой карточки, которая эту смену вызывает, — не отдельной, задержанной анимацией); фейд каждой строки `PuzzleResult` |
| `motion.duration.medium` | 200 мс | Подъём карточки при захвате (`elevation.resting` → `elevation.dragged`, `motion.easing.standardAccelerate`); возврат после отпускания использует то же значение с `motion.easing.emphasizedDecelerate` |
| `motion.duration.long` | 300 мс | Перестановка позиции карточки в списке; вход нового экрана при навигации (`motion.easing.standardDecelerate`) |
| `motion.duration.exit` | 200 мс | Выход текущего экрана при навигации (`motion.easing.standardAccelerate`) — короче входа по правилу «выход быстрее входа» |
| `motion.stagger.resultReveal` | 60 мс | Сдвиг между появлением последовательных строк на `PuzzleResult`. Значение зафиксировано `UX_FLOW.md` (раздел 5) и перенесено без изменений — не пересчитывается и не округляется до шкалы `motion.duration.*` |
| `dragHint.wobbleDuration` | 300 мс | Однократное покачивание первой `OrderableCard` в `DragEducationHint`. Значение зафиксировано `UX_FLOW.md` (раздел 2) и перенесено без изменений |
| `dragHint.wobbleAmplitude` | 4° (поворот) | Амплитуда покачивания — небольшой поворот карточки туда-обратно, не смещение позиции. Подобрана как «достаточно заметно, чтобы прочитаться как намёк, недостаточно, чтобы прочитаться как игровой bounce»: меньше типичной амплитуды спортивных/игровых wiggle-эффектов (обычно ≥ 8°) |
| `dragHint.autoHideDelay` | 4000 мс (4 с) | Автоскрытие плашки `DragEducationHint`, если пользователь не взаимодействовал с карточкой. Значение зафиксировано `UX_FLOW.md` (раздел 2) |
| `dragHint.submitLockDuration` | 600 мс | Время, на которое `PrimaryButton` «Проверить» остаётся `disabled` после появления `DragEducationHint`, чтобы случайный тап не проскочил обучение (`UX_FLOW.md`, раздел 2) |
| `motion.rotation.chevronExpand` | 180° | Угол поворота шеврона `SourcesBlock` между состояниями `collapsed`/`expanded`; анимируется за `motion.duration.short` (100 мс) |

**Reduced motion.** Если активна системная настройка сокращения анимации: все `motion.duration.*` → 1 мс, `motion.stagger.resultReveal` → 0 мс, все `motion.easing.*` → `motion.easing.linear`. Переходы не вырезаются из графа анимации, а сжимаются — это исключает рассинхронизацию состояний, зависящих от `AnimationSpec.finishedListener`.

**Исключение — `dragHint.*`.** `dragHint.wobbleDuration`/`dragHint.wobbleAmplitude` при reduced motion обнуляются (покачивания нет вовсе, не «очень быстрое покачивание» — резкий поворот на 1 мс выглядел бы как визуальный дефект). `dragHint.autoHideDelay` и `dragHint.submitLockDuration` **не сокращаются** — таймер видимости плашки и блокировка «Проверить» остаются полноценными 4000 мс и 600 мс: это не декоративная анимация, а часть обучающего таймфрейма, отключать которую reduced motion не должен.

**Запрещённые параметры.** `dampingRatio` физической пружины (`spring()`), если она где-либо используется, не может быть ниже `Spring.DampingRatioNoBouncy` (1.0) — то есть пружина без «перелёта» разрешена, пружина с видимым отскоком — нет.

## 6.10 Адаптивность

| Условие | Правило |
| --- | --- |

Отдельная «раскладка для больших телефонов» не создаётся — M3 window size classes не выделяют такой класс отдельно от compact |

| Системный шрифт 200% | Компоненты растут по высоте, никогда не сжимаются по ширине текстовой части и никогда не уменьшают touch target/иконки/индексную зону/срез угла. Следующий этап (Design Gate, часть B2) даёт ровно 12 артбордов: Home, Puzzle, PuzzleResult и DayRecap — каждый в светлой и тёмной теме (8 артбордов) плюс по одному 200%-варианту на каждый из этих четырёх экранов (4 артборда). `Archive` и `Settings` остаются state sheets (`COMPONENTS.md`) и отдельных полноэкранных артбордов, в том числе на 200%, не получают — их 200%-поведение проверяется через поведение составляющих их компонентов (`Archive row`, `Settings row`, `Statistics block`), уже описанное в этом документе и в `COMPONENTS.md` |
| Edge-to-edge | `enableEdgeToEdge()` включён на уровне `MainActivity`. Отступы под системные панели — не токены `spacing.*`, а динамические значения `WindowInsets.statusBars`/`WindowInsets.navigationBars`, применяемые через `Modifier.windowInsetsPadding` в месте фактического использования: верхний inset — к `AppTopBar` на `Puzzle`/`PuzzleResult`/`Archive`/`Settings` и к `HomeHeader` на `Home` (`DailyIssuePanel` верхний inset не несёт — он не самый верхний контейнер экрана), нижний inset — к контейнеру, в котором закреплена `PrimaryButton` внизу экрана. Значение «28 dp» в иллюстративных отступах `concept-d.svg` было условной заглушкой для статичного борда — реальная реализация не хардкодит это число нигде |
| Safe drawing insets | Дополнительно учитывается `WindowInsets.safeDrawing` там, где на устройстве есть вырезы/скругления экрана — тем же механизмом `windowInsetsPadding`, без отдельных токенов |
